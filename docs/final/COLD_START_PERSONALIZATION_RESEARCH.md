# 冷启动与学生个性化调研及落地建议

调研日期：2026-10-17。代码基线：`2e5465d`。状态：**调研与实施提案，尚未实现**。本文件补充现有产品规格，不把拟议能力计入已交付功能。

后续实施更新：同日的[产品体验升级](PRODUCT_UPGRADE_2026_10.md)已接入部分提案：本人学习方向持久化、无题知识卡/例题入口、诊断驱动的路线入口和可追溯地图。独立入门短测、全学科覆盖与每日计划调度仍为提案。下文保留调研时点的事实和完整方案。

## 1. 结论与范围

用户指出“今日”页首次打开空白，系统需要针对学生个性化。检查结果支持改进这一流程：当前产品擅长处理学生带来的错题，但缺少没有错题时的起点；现有学习记录也没有形成统一的每日推荐。

建议把学生路径补齐为：**选择眼前目标 → 开始一个适合的小任务 → 获得具体反馈 → 保存学习证据 → 决定下一步**。首页负责回答“现在做什么、为什么适合我、做完到哪里”，其余功能仍留在原有导航里。

本轮是代码审查、运行态读取、官方产品资料调研与设计推演，未开展真实学生访谈或可用性测试。用户的体验反馈是一个直接意见，不能代替群体研究；下面的数量、优先级、用时均是待验证的产品策略。

## 2. 当前系统证据

| 观察 | 证据 | 对体验的影响 |
| --- | --- | --- |
| 首页是规则分支，不是每日学习计划 | `frontend/src/pages/index/index.vue`：任务、旧会话、到期复习、教师任务，最后回落到录题 | 无这些记录时主要只剩录题；完成任务后也缺少合适的收尾 |
| 其他任务行依赖已有数据 | 同文件 `otherTasks`，最多两行 | 新学生没有复习、误区、教师反馈时整块消失 |
| “练一类题”仍回到自己的题目列表 | 同文件 `chooseTask` → `pages/problem/list?purpose=practice` | 没有个人题目的学生无法通过这个入口直接开始练习 |
| 注册只收集年级等基础信息 | `pages/register/register.vue`、`account_api.cj` | 未取得主学科、当前章节、短期目标与可用时间 |
| 已有画像存储，未接成学生设置流程 | `student_profiles` 已有 `grade/learning_goal/preferences`；注册把目标设为统一值、偏好设为空对象 | 可以复用，不需要另建一整套身份或画像系统 |
| “我的”尚无学习偏好编辑入口 | `pages/profile/profile.vue` | 学生无法主动纠正系统对学习目标的理解 |
| 首页数据并非完全没有个性化基础 | `dashboard.cj` 已有本人掌握估计、误区、复习、继续学习与教师任务 | 缺的是可信的汇总和推荐决策，不能只添加姓名问候 |
| 现有练习推荐必须绑定个人错题 | `practice_recommend.cj` 要求 `mistake_id` 和已分析的目标知识点 | 不能把现有接口直接当作无历史入门练习接口 |
| 现有持久教学任务有严格来源门槛 | `learning_tasks.cj` 要求本人的已确认题目、有效分析与参考答案 | 示例体验、章节摸底需要明确的新来源合同，不能伪造一条学生错题绕过验证 |
| 已有可复用教学记忆 | `learning_memory.cj`、`learning_memory_compute.py`，详见 `MEMORY_IMPLEMENTATION.md` | 后续教学可据有效证据调整，避免再次开发独立掌握分 |
| 首页存在错误和空数据混淆风险 | 学习任务读取失败被 `.catch(() => [])` 转成空数组 | 推荐可能误以为没有任务；应区分“暂无任务”和“任务暂时加载失败” |

运行态只读核验：公开账号 `1@1.com` 已有一条题目记录，年级高一；复习数、掌握点数、教师任务数均为0，掌握和误区数组为空，继续学习为空、持久任务数为0。它已经不是严格的空白新账号，不能把该结果当作零历史实测。按当前首页分支，它仍回落到录题卡，说明“已有题但尚未形成学习路径”也需要处理。核验没有提交作答、重置账号或调用模型。

另有两个统计口径应在计划接入前修正：`weekly_questions` 当前查询没有限定本周；`streak_days` 当前统计的是录题日期，不能直接称为完整学习连续天数。无证据时不显示伪精确的学习画像。

## 4. 按行为区分学生需求

| 场景 | 学生眼前的任务 | 合适起点 |
| --- | --- | --- |
| 手边有一道不会的题 | 把卡住的一步弄懂 | 拍照或手动输入自己的题，继续现有诊断与教学 |
| 没带题，不知道学什么 | 轻松开始并找到方向 | 选择学科/当前章节，从一组短练习或例题开始 |
| 已有学习记录 | 接着上次学习，补容易忘的内容 | 继续任务、少量到期复习、已观察到的薄弱点 |
| 临近考试 | 在有限时间内复习指定范围 | 学生选择范围和时间，再生成有边界的计划 |
| 今天已完成或很久没来 | 看见完成结果，决定是否继续 | 明确完成与休息入口；回归时重新确认章节，不按旧目标堆任务 |

同一学生会在这些场景间变化，不固定贴“学困生/尖子生”标签。年级也不能决定真实能力或教材进度。

## 5. 冷启动流程

### 5.1 首次进入：轻量设置，随时跳过

注册保留已填写年级，不重复询问。首次在首页显示简短的可关闭设置卡，分步询问：

1. “现在想学哪一科？”先选一个当前学科，以后可切换。
2. “最近在学什么？”选择已有知识目录中的章节；提供“不确定”，不强制填写教材版本。
3. “今天想怎么开始？”解决自己的题 / 练几道找方向 / 看一道例题。

每天可用时间默认建议10分钟，提供5/10/20分钟与“今天再说”；它是可修改的计划预算，不是监督性承诺。更多考试日期、教材等按需补充，不把首次使用变成问卷。跳过后依然能录题、浏览和选择内容；不能为省事默认把所有人设成初二数学。

### 5.2 三种起点的边界

**自己的题**：完整复用录入、核对、分析与持久教学任务，失败和恢复沿用现有机制。

**短练习**：在学生选定且有内容覆盖的章节内，建议3题、最多5题，一次呈现1题。允许“还没学过”“暂时不会”“换一题”、暂停和退出；这些动作不等同错误答案。根据本次独立作答给出局部建议，例如“这组方程练习里，去括号值得再练一次”。3题不能证明全年级能力、全学科水平或精确掌握率。

**例题体验**：展示明确标注的教学例题，学生可查看一步提示并亲自尝试下一步。展示的示范解法、示范错误不属于学生作答，不写入学生误区或错题。只记录学生实际产生的交互；纯浏览不计独立掌握证据。

题源不足时应能退回知识卡、选择其他已有章节或录入自己的题。不能把不相关题目、缺答案题或模型临时编出的未经检查题目补成“个性化摸底”。

### 5.3 首次结束

给出一条具体反馈、一条下一步建议，允许学生结束。示例：“这次独立完成了2题，去括号这一步还可以再练。下次从这里继续。”题数和结论必须来自真实事件；不展示没有依据的能力雷达图或“超过多少同学”。

## 6. “今日”页结构与状态

保持既有底部导航。页面从“任务缺失时显示录题按钮”升级为“有状态的学习起点”。首屏建议只包含以下三层，随着状态替换内容：

1. **简短上下文**：问候 + 当前学科/章节，允许点击修改；缺项时显示选择入口。
2. **一个主任务卡**：具体任务、预计用时、选择原因、一枚主按钮。卡片只有一个主行动。
3. **最多两个辅助入口**：有自己的题可录入、换个方向；有真实记录时替换成简短进展或待办。更完整功能留在学习中心。

新学生无历史的示意文案：

```text
下午好，小林                         数学 · 章节待选

今天从这里开始
练几道，找个适合的起点
选一下正在学的章节，每次只做一道。
                    [选章节并开始]

带了自己的题？录入题目              先看一道例题

今日        错题        学习        我的
```

这是信息结构草图，不是已经完成的界面。未选章节前不写“根据你的水平推荐”。主按钮到选择再到开题，必须是一条完整可用路径。

| 状态 | 主卡 | 辅助内容 |
| --- | --- | --- |
| 零历史、未设置 | 选学科/章节，开始第一次学习 | 录自己的题、例题体验 |
| 已设置、未作答 | 适用章节的短练习；题库不足则知识卡 | 修改范围、录题 |
| 已有未分析或未开始学习的题 | 回到自己的题，完成核对/分析或开始学习 | 自主练习 |
| 有有效未完成任务 | 显示实际卡点和恢复入口 | 到期复习/教师安排，最多两条 |
| 有到期复习 | 本次可承受的小批复习，不把所有积压一次塞满 | 查看全部、调整今天用时 |
| 有临期教师任务 | 展示任务及实际截止信息，允许切回自己的学习 | 继续任务/复习 |
| 今天完成 | 告知真实完成内容，“今天先到这里” | 自愿再练；不自动新增必做任务 |
| 长期未使用/目标变化 | 确认最近学到哪里，再给少量练习 | 原记录可回看，不按旧画像硬推荐 |
| 数据读取失败 | 具体失败与重试；仍可用的模块保持可访问 | 不显示“无记录”或“今天暂无待办”掩盖故障 |

视觉延用当前色板与圆角，不增加巨幅插画、自动轮播和满屏数字。正文可读、按钮至少44px，窄屏和字体放大不溢出；主按钮清楚、次入口较轻。预计用时标“约”，不得伪装成精确预测。

## 7. 个性化覆盖整个系统

| 环节 | 输入 | 具体改变 | 学生控制与约束 |
| --- | --- | --- | --- |
| 内容范围 | 年级、学科、章节、是否已学 | 缩小题库和知识卡范围 | 学生可改；不把入库标签直接视为教材对齐 |
| 题目选择 | 有效作答、独立/辅助区别、难度估计、已见题 | 选择合适题型与下一道题 | 可换题；无证据先保守起步，不显示假能力分 |
| 单次教学 | 当前解题步骤、错误候选、有效记忆 | 分步提示、核对关键理由、必要时补先修知识 | 可要求更简短/更详细；显示答案不算独立完成 |
| 复习安排 | 真实复习结果、到期计划、当天时间 | 控制批次，优先值得复习的内容 | 可延后、结束；自评难易不代替判题 |
| 每日计划 | 目标、在学内容、任务、复习、时间预算 | 给出有理由的1个主任务和少量候选 | 可换方向；教师任务与自主计划分别标明 |
| 报告 | 同口径学习事件和证据 | 展示做过什么、哪一步有进展、证据是否不足 | 不把短测推广为总能力，不把浏览计为掌握 |
| 学习设置 | 学生明确选择 | 修改时间、目标、章节、讲解长度 | “我的→学习设置”；不固化视觉型/听觉型学习标签 |
| 教师/家长 | 既有授权和关联记录 | 看真实完成与待帮助内容 | 不扩大现有权限；学生偏好不被模型静默重写 |

先通过明确规则实现可解释推荐，不需要训练深度推荐模型或引入多智能体框架。模型负责既有教学与受约束的规划计算，首页打开不调用LLM。

## 8. 画像、计划和智能体职责

画像分三层：**学生自己选择的目标与偏好、可追溯的学习事件、系统形成的有置信边界的估计**。学生说“这章不会”是自述，练习答错是事件，“某一步可能薄弱”是估计，三者不能混写。

建议最小偏好字段：`schema_version`、当前学科、当前知识点/章节标识、`goal_mode`、`daily_minutes`、`explanation_depth`、设置完成/跳过状态及版本。可复用 `student_profiles.preferences`；当前学科和目标是选择，不是能力判断。知识点掌握与误区继续使用既有表和有效记忆合同。

智能体形成有边界的循环：仓颉读取有效画像和事件 → 规则筛选候选 → 必要时Python给出结构化教学计划 → 仓颉校验允许内容与工具 → 学生开始/作答 → 验证结果 → 保存证据并调整后续建议。推荐理由只给公开依据，不返回内部推理或完整模型上下文。

推荐规则先采用以下明确优先级，具体时间阈值集中配置：

1. 尊重学生刚选择的目标；允许随时切换，保留原任务。
2. 检查临期教师安排与有效未完成任务；有冲突时显示另一个候选，不悄悄覆盖。
3. 从到期复习中按时间预算抽取一小批。
4. 选当前范围内有证据值得巩固的知识点；只有单次证据时以“再确认”表述。
5. 无有效证据时提供章节短练习；无可用练习时提供知识卡/录题路径。
6. 今天预算已完成时显示完成状态，进一步学习由学生主动发起。

同日不因每次刷新随机换任务；实际作答、主动换任务、教师安排变化或源内容失效时重新计算。失败任务不能长期占据首页，必须显示恢复方式并允许选择其他任务。被删除、改版、撤销或失去权限的来源按既有合同重新验证。生成推荐、查看示例和打开首页均不写入掌握证据。

| 仓颉计划 | 持久化同日选择、状态、实际完成关联与规则版本 | 暂定 `daily_learning_plans`；不复制一套题库或认知事件。先核对现有学情计划表，能复用则避免新表 |

| Python | 复用规范化、判题、SymPy与记忆；按需增加初始候选排序计算 | 输入输出经Pydantic；Qwen仍通过ApiPoolProvider轮询，首页排序尽量不用模型 |
| 题源准备 | 按学科/年级/章节盘点可展示、可自动判定、有图、有答案的实际题量 | 当前1770入库、1442索引为已有交付记录，数量不等于所有章节可用；实施前重查实时覆盖 |

入门练习与例题不能直接伪装成已分析的个人错题。第一版先独立记录入门会话并复用判题；需进入现有教学任务时，增加明确的题库/例题来源快照与版本校验合同，审查题目归属、作答归属和记忆写入资格。学生确实做错并主动保存后才进入个人错题本；重复提交必须幂等，提交前不泄漏标准答案。

若需新表，使用MySQL增量迁移，版本号在实施时接续当前最大版本；本调研不创建表或改生产数据。旧账号无偏好时进入可跳过设置，不强迫重新注册。已有学习证据保留，不因画像修改追溯重算。规则版本变化与计划更新要能审计，但不额外保存敏感对话副本。

## 10. 建议实施顺序与验收

| 阶段 | 交付 | 验收重点 |
| --- | --- | --- |
| P0：起点与真实状态 | 首页状态分类、已录题未开始入口、学习设置保存、局部失败和完成态；修正统计口径 | 新账号知道下一步，已录题账号可直接回题；接口错误不变成无历史；刷新/重启设置不丢；不能以按钮通向空列表冒充解决冷启动 |
| P1：无题可学的最小闭环 | 选择真实有覆盖的章节，完成短练习或例题体验，反馈与继续/结束；记录来源 | 没有个人错题也能完成一次真实学习；不伪造错题、掌握与误区；自动判题不足时有可用退路 |
| P2：每日个性化闭环 | 用有效证据串联计划、复习、当前任务和教学记忆；补报告关联 | 相同年级但不同有效作答获得不同且有依据的建议；教师安排冲突可解释；刷新不乱跳；只看答案不升级独立证据 |
| P3：学生验证与收敛 | 小规模试用，按真实阻碍改文案、步骤、任务长度与推荐 | 先验证找到起点和完成流程，再评价推荐帮助；不靠增加首页密度解决问题 |

P0和P1共同构成冷启动可用版，只有P0美化首页不算完成。P2才使“整个系统个性化”形成闭环。无需同时扩张全学科大题库、考试预测、商业推荐或多智能体基础设施。

必要检查按改动执行：前端状态/导航和偏好持久化；仓颉本人权限、字段校验、版本冲突、MySQL迁移与重复提交；算法结构校验和判题；真实浏览器从无题开始到结束以及刷新/断网恢复。功能完成后运行 `make verify-final`，保留旧接口兼容检查；不以模拟接口截图替代真实端到端闭环。

## 11. 研究验证计划

建议邀请5–8名有不同使用行为的初高中学生进行探索性可用性测试，覆盖有题来学、无题开始、已有记录和临期复习；这是小样本发现问题，不宣称统计代表性。测试只使用必要的学习材料，避免收集学校、排名、家庭等无关信息。

任务：首次进入找到合适起点；没带错题完成一次学习；中途退出后继续；修改学科与章节；今天完成后结束。主持人不提前指路，分别记录观察到的行为和学生事后意见。

观察指标：找到可行动起点的时间、开始/完成/退出次数、跳过设置比例、返回空列表次数、推荐不合适的理由，以及学生能否解释为何推荐。把首次找到入口30秒作为待检验的可用性目标，非当前结果；短练习时长从试用数据调整。演示和自动测试事件不计真实使用留存。

学习质量单独看同知识点的独立作答与后续复习表现；多点几次、完成更多任务不自动意味着学得更好。现阶段没有学生试用数据，不给留存率、提分幅度或推荐准确率承诺。
