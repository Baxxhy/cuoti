# 学习入口统一

## 本轮计划

1. 诊断页与详情页的默认学习入口共用仓颉持久任务创建/恢复；用同一个用户/题目请求编号处理丢失回执和重复点击。
2. 原完整引导教学保留在详情“学与练”，明确进入教学会话；默认订正任务与讲解各有入口，不依赖碰巧的journey跳转。
3. 创建失败显示可重试的页面反馈；返回页面重读当前题目；隐藏页面或账号变化后的迟到结果不能跳转/覆盖当前界面。
4. 用前端行为、真实仓颉浏览器/恢复以及实际现有题核对路径，完成相关构建与完整回归后提交。

基线发现：诊断页主按钮仍直接POST教学会话，详情主按钮已使用learning-tasks；完整引导按钮却优先跟随journey，可能又进入诊断或订正。原详情创建仅保存本地请求编号，没有捕获失败以持续提示。此轮不重写后端，不新增数据库、模型调用通道或备份。


## 实际实现与专项

- 默认详情/诊断入口共用`requestLearningTask`：先从仓颉读取本人身份，按用户/题目保存创建编号，同一在途请求共用回执；请求失败保留编号，确认回执后清除。账号变化的旧回执不交给页面。
- 有错诊断和未发现错误均可进入持久任务；需核对的诊断继续提供知识核对。完整引导学习位于详情“学与练”，准备齐全时明确创建教学会话，避免跟随journey再次回到订正入口。
- 页面返回重读题目；隐藏/卸载递增读取代号，迟到加载不能覆盖新页面，迟到创建不能突然跳页。创建失败持续显示重试说明，忙碌时按钮显示真实准备状态。
- 前端150项/39文件与类型检查通过；新增测试覆盖同题并发、丢失回执编号复用、账号变化、未发现错误直接进入、页面返回刷新和迟到响应。
- 现有真实不等式和正确一次方程样本上的2项浏览器专项退出0：实际先提交创建后丢弃回执，重试使用同一编号；诊断与详情恢复同一任务，未提交草稿刷新保留；未发现错误直接独立作答且不计掌握。完整引导部分仅控制呈现回复，未调用新模型，其仓颉业务由完整原生回归另验。日志`/tmp/zhiwei-task-entry-actual-browser.log`。

最终`CANGJIE_VERIFY_FOCUS= make verify-final`已退出0：前端150项/39文件、类型检查、H5/App本地资源构建、算法171项、仓颉31组、完整HTTP/MySQL与进程重启恢复、浏览器41项通过，0跳过。日志`/tmp/zhiwei-task-entry-final.log`。 实际服务`make check-final`四项就绪。
