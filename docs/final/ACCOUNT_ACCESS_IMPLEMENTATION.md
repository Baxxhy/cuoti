# 账号页面可用性与恢复

## 本批计划与范围

在既有蓝白样式下完善登录、注册和修改密码：关联可见标签与实际输入，支持密码管理器与键盘；失败后持久反馈并保留当前输入；检查360/390/430窄屏、200%文字与缩小可视高度。复用原仓颉账号接口、角色跳转和会话合同，不新增账号系统或数据库迁移。

## 实际问题与修改

- 实际H5登录页中，邮箱没有可访问名称，失败3秒后没有持久错误提示。修改密码页的4个输入在文字放大时存在行高裁切。
- 新增`account-field`：H5使用原生label/input，明确邮箱、密码和昵称的自动填充用途；App条件编译继续使用uni-app输入，密码保持掩码。只保存当前页内输入，不将账号密码新增到本地草稿或日志。
- 输入高度随文字行高增长，正文16px，沿用既有边框、蓝色焦点和留白。目视发现原生输入未继承uni-app转换后的全局盒模型，已显式使用border-box；新增输入框不能超出容器的断言。
- 注册H5年级使用有标签的原生选择器，保留初一至高三全部选项；App继续使用原picker。昵称/邮箱提交时去首尾空白，不裁剪密码。
- 登录、重复邮箱和修改密码失败均保留字段并显示可读错误；失败后可原地修改和重试。新密码两次输入不一致先在页面提示；不把未提交当成功。主按钮与登录页次入口补可访问角色及Enter/Space操作。
- 浏览器验收登录定位改为可见标签，注册年级改为原生选择器操作；没有跳过旧学习、恢复或角色用例。

- 初次完整回归在H5构建阶段主动停止，以修复目视发现的盒模型问题，未记为通过。第二版布局用例等待各页唯一字段出现，避免切页未完成就重复放大旧页面；截图前回到页顶。uni-app还会缓存旧页，新增强制刷新和16px→32px实际字号断言，保证每次是200%而非累计400%。

## 边界

浏览器200%文字检查不是原生系统字体或原生键盘验证；缩小视口只证明H5中可滚动到输入与提交，不能替代Android/iOS真机。自动填充属性与原生标签已核验，不声称验证了所有密码管理器。此次不增加忘记当前密码后的账号找回机制，“修改密码”仍需正确当前密码。
