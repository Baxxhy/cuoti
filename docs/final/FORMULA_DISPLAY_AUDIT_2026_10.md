# 2026-10-19 · 全程序页面公式显示排查

## 原因与修复

错题列表先前已接入公式组件，但组卷、复习反馈、旧教学分支及教师页面仍有直接插值显示学科内容的入口。仅检查题干字段会漏掉答案、知识名、教学解释、历史对话和复核证据。

本次逐项检查 `frontend/src/pages`、`frontend/src/components` 的模板插值、动态内容、原生选题器和文字截断位置。涉及33个页面/组件的显示修复，复用现有 MathText/KaTeX 渲染；HTML转义、`trust: false` 和坏公式原文核对机制沿用现有实现。学科内容显示与编辑框分开，编辑框仍保留可编辑的原文，不改写后台题目。

| 范围 | 修复内容 |
| --- | --- |
| 组卷 | 候选题、知识点、试卷历史名称和编辑预览接入公式组件；完整题干在渲染后换行，保留选题、排序、分值和保存 |
| 学生学习 | 首页继续学习、诊断答案、练习/复习反馈、考试反馈、作业标题与反馈、学习任务标题及教学记录 |
| 原教学流程 | 答案对比、关键解释、选项说明、教学标题、复述起句、关键词、完成说明和历史对话 |
| 知识与档案 | 知识卡名称、章节、相关基础、知识图谱节点及详情、错因分类、修复路线、学习档案、报告建议 |
| 图示 | 互动演示的题干、标题、目标、任务、观察点与变量标签；图形核对说明和图示历史 |
| 教师与管理 | 题目列表、待复核队列、学生/参考答案与步骤、判题说明、学习建议、教学轨迹与认知知识字段 |

知识图谱不再按源码字符数截断名称，避免切断 `\frac` 等命令。教师布置题目的原生选择框不能渲染公式，改为可展开的公式题目列表，选择后保留原题ID并收起。共用公式容器设置1.8倍行高，为分式和上下标留出空间。菜单、人数、日期、状态、技术JSON等普通界面数据保留原有显示方式。
