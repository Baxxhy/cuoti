# 智能体长期记忆实施合同

本批按最终智能体规格补齐长期记忆。沿用009任务工作快照与既有MySQL记录，不新建另一套掌握分，也不将学生自述当作判题事实。实现与验证状态以实施进度为准。

## 实施顺序

1. 给新写入的认知更新、复习判定保存来源版本；接通题目、参考、题库、本人作答/会话和老师复核的验证。
2. 仓颉按本人/学科读取有界记忆：掌握估计、误区候选、有效作答更新、复习结果、复习安排、学生确认要点。每条附分类、来源ID、版本、观察与到期时间。
3. 摘要按每次执行重建；当前任务与旧教学会话共用该读取合同。开始计算与提交结果前分别重读，不把已删除/撤销/改版/过期记录继续传入规划器。
4. Python校验记忆结构，明确区分估计、候选、自述和已判定事件；引用必须属于本轮有效清单。无模型时也验证历史错误能影响支持路径，不能只增加字段。
5. 通过真实MySQL专项验证用户/学科、旧版未知来源、有效期、编辑/删除/撤销、来源改变、在途更新和审计引用，再跑完整回归并提交。

## 分类和有效期

| 类型 | 记忆语义 | 本项目有效期/上限 |
| --- | --- | --- |
| 掌握记录 | 估计，不是掌握证明；缺少历史来源时明确为旧估计 | 更新后30天，最多3条 |
| 活跃误区 | 待核对候选，不是学生定性 | 更新后30天，最多3条 |
| 作答认知更新 | 仅接受来源仍有效的新格式事件，区分独立/辅助/老师复核 | 90天，最多4条 |
| 复习结果 | 本次已确认的系统判定，学生难度自评不代替正确性 | 90天，最多3条 |
| 自检要点 | 学生确认的自述，删除或题目版本变化立即排除 | 更新后90天，最多3条 |
| 待复习安排 | 当前有效安排，只作提醒，不证明学会 | 更新后90天，最多2条 |

总计最多18条。期限是可版本化的项目策略，并非已证明的遗忘定律；不修改原记录或让过期记忆自动扣分。旧的无来源判定不升级为已验证事实；保留原业务历史供学生回看。估计和候选不因一次正确作答升级为事实。

来源指纹覆盖与教学有关的题目、原作答、分析/参考及必要外部题库版本；归档/失去确认、老师撤销和原任务失效分别检查。收藏、界面标题等展示变化不应误判成答案变化。摘要只包含受限文字和实际状态，不传入原始答案、凭据或整段对话。

记忆读取本身不写认知更新。删除自检要点只删除其未来规划用途，保留既有删除审计。有效记忆在一次计算期间改变时，该次结果不提交；恢复时读取新记录后重新规划。

## 实际实现与兼容

- `learning_memory_sources.cj`校验来源，`learning_memory.cj`分类读取；`learning_memory_compute.py`校验结构、类别、期限上限和引用清单。
- 新元数据保存在既有cognitive_updates.evidence与review_records.grading_details，原业务写入及事务不拆分，无新数据库迁移。正式仓颉库仍要求009。无来源旧判定保留历史，但不作为新版已验证事件。
- 来源指纹覆盖教学相关题目、原作答、图形资产、分析参考及必要教师/题库版本。新版复习判定若在反馈前遇到来源更新，会要求重新作答；旧无指纹记录按原接口兼容，但不会因此获得记忆事实资格。
- 当前任务和旧教学会话共用新读取；旧Python算法的无记忆合同保留逐项兼容测试。错误历史能在无模型时选择步骤对齐，学生自述仅作为有标签的数据供规划参考。
- 审计清单包含source_refs、版本、分类和时效，不直接复制要点全文。历史对话、已经给出的教学文本及原有过程记录中的当时摘要仍按原记录保存，删除要点影响未来规划用途，不追溯改写旧记录。
- 单条受限摘要最多400字，完整记忆清单最多18条；简要摘要另有限长，规划同时收到带分类的完整受限条目，不把无限对话塞进上下文。

专项命令：`CANGJIE_VERIFY_FOCUS=task-memory make verify-cangjie`。它使用临时隔离MySQL及本地模型协议模拟，不访问真实模型池，不替代完整`make verify-cangjie-browser`、真实算法质量和学生试用门槛。
