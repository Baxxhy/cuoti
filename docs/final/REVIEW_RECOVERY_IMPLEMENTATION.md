# 复习恢复与页面整理

## 实施计划

1. 到期列表返回当前题目版本及本人最近一次有效待评价判题回执；不在首次作答前返回参考答案，不恢复来源已更新的旧判题。
2. 复习提交增加可选请求编号与来源版本；同一编号重试复用已保存回执，不重复判题建记录，载荷改变明确拒绝。
3. 页面保存按账号、计划和来源版本隔离的文字草稿及待确认提交；刷新/返回重新读取服务器状态。失败保留内容并持续显示重试说明，评价回执丢失时从真实历史核对是否成功。
4. 一次突出当前题；巩固建议、历史按需展开，补键盘操作与手机排版。照片原图继续由既有上传流程保留；草稿保存已有照片引用和识别文字，恢复预览不重新上传、不覆盖学生修改的答案。
5. 行为测试、真实仓颉/MySQL的回执重放和来源变更检查、浏览器恢复/失败专项与完整主线回归；观察完成结果后更新记录并提交。

基线：复习页仅onLoad读取，文字和判题回执仅保存在页面，提交/评价失败没有持久反馈；全部巩固建议默认展示。判题后pending记录已经在MySQL，但列表不返回；故先补服务端恢复合同，再整理页面，不用本地缓存冒充服务端判题。

## 当前实现

- 仓颉`reviews.cj`按本人/计划读取当前题目版本，返回与该版本匹配的待评价回执；首答前仍不返回原答案或参考答案。回执只投影公开判题字段，照片链接重新签名。
- 提交可带`request_id`和`source_version`。计划行锁下检查已有回执，同编号/同载荷复用结果；载荷或来源改变拒绝。新提交替代旧待评价记录；评价同样锁计划，旧作答不能更新计划。沿用现有JSON字段，无新增迁移。
- 页面按账号/计划/来源版本保存文字、已有照片引用及在途提交编号；账号退出沿用任务草稿清理。刷新优先读取真实待评价回执；主动修改待核对结果后，旧回执不覆盖新草稿。照片预览恢复不改变已编辑文字。
- 判题回执丢失时读取当前列表，仅接受本次请求对应的回执；评价回执丢失时从真实历史匹配记录/计划的完成状态，不假定提交成功。
- 隐藏页面停止消费旧回执，返回重新读取；当前作答忙碌期间禁用编辑/重复动作。缓存失败提示保持页面打开，仍允许提交。
- 当前题优先，巩固建议与历史主动展开后才读取；补充接口失败不阻断复习。错误提示位于当前操作后，保留答案与可重试按钮。
