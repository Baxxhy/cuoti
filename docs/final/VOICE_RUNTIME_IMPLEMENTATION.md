# 语音内部能力实际恢复

## 本轮计划

1. 用固定公开句子复现现有edge-tts失败，核对官方协议修复版本；升级并固定已验证依赖。
2. 从真实合成音频解码验证非空音频，再用已有Whisper缓存进行中文转写，明确实际与模拟证据。
3. 重启实际算法服务，验证仓颉鉴权、文件、音频下载与转写持久化；专用临时测试数据完成后清理。
4. 运行相关算法/兼容与主线检查，更新启动和交付记录；保留已有前端移除语音的约定，不擅自恢复入口。

基线：edge-tts7.2.8，实际朗读曾返回502；faster-whisper-small已有本地缓存。官方[7.3.0](https://github.com/rany2/edge-tts/releases/tag/7.3.0)新增Sec-MS-GEC v2支持，[7.3.1](https://github.com/rany2/edge-tts/releases/tag/7.3.1)修复服务端日期解析。依赖变化是否解决本机问题仍以本轮实际结果为准。


## 实际结果（2026-10-17）

- 原7.2.8使用固定公开句子实际失败，异常为WSServerHandshakeError；升级至7.3.1后同类合成成功，项目依赖固定为该版本，pip check通过。
- 真实MP3为33552字节，PyAV解码233帧。已有Whisper-small缓存完成转写；没有下载新模型、增加语音引擎或模型调用通道。
- 实际仓颉接口完成合成→签名音频下载→上传转写；MySQL两类完成记录及对应文件存在已直接核对。临时核验脚本首次未识别默认媒体目录，在接口成功后清理阶段失败；按仓颉工作目录修正为backend-cangjie/media后完成核验与清理。仅本轮临时账号、语音记录和音频清理，已有学习数据保留。
- 固定文本：“因为等式两边同时减去相同的数，所以移项表现为变号。”；实际转写：“因为等式两边同时减去相同的数,所以一向表现为变号。”。关键字检查通过不代表逐字准确，“移项”被识别成“一向”，不能把未经核对的口述当作学生确认的答案。
- 171项算法及保留Python模块297项测试通过，Ruff与依赖检查通过；本轮未改仓颉或前端源码，复用上一批166项前端/44项浏览器、31组仓颉、HTTP/MySQL/重启的有效证据，不宣称本轮重新执行了整轮make verify-final。
- 实际服务已重启载入新依赖，make check-final四项就绪。前端的语音移除测试与入口设计保留；本项是内部接口恢复，不代表学生端新增语音页面。

日志：`/tmp/zhiwei-voice-algorithms-v2.log`、`/tmp/zhiwei-voice-compatibility.log`、`/tmp/zhiwei-voice-api-actual-v2.log`。私有结果`.runtime/live-voice-check.json`忽略且0600，不含令牌或签名音频URL。

首轮算法回归在普通沙箱中等待退出；用最小asyncio线程回调对照证实，普通沙箱输出完成后仍超时，本机环境立即退出。仅停止本轮受影响进程后在本机环境重跑，171项已退出0；该等待不计通过。

## 可复现检查

先按系统说明安装依赖并运行make dev-final。实际语音需要可连接的朗读上游及Whisper模型缓存；当前本地缓存已用于核验。

```bash
.venv/bin/python scripts/check_voice_cangjie.py --api-base http://127.0.0.1:8002/api/v1 --token-stdin
```

命令从标准输入读取本人令牌，交互终端不回显，不把令牌放进参数或报告。该主动检查会在本人账号下创建两条语音记录；输出固定句子的转写、音频摘要和记录编号，不读写题目或原作答。它先核对目标为仓颉服务，避免误测旧Python业务入口。未连接上游或没有有效模型时明确失败，不以模拟音频替代。
