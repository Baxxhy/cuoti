# 总体方法：Sivia 绘制提示词

交付用途：Word正文中的可编辑矢量示意图。画布900×760，置入宽16.4cm；PNG导出3倍尺寸。

构图与关系：输入从上方进入。Python侧解释结构化与诊断计算，仓颉侧负责来源版本、任务调度与资格校验。计算候选结果通过业务校验形成下一步；新作答沿反馈线返回。数据库写入归仓颉，不能把模型输出直接连成掌握结论。

视觉规则：白底，证据暖黄#fff0cd，计算浅蓝#d6eafa，业务浅绿#cfece1，核对浅橙#f8dcc9，工具与并列分支浅紫#e5ddf4。全部标签#000000。纸页表示原始材料，六边形表示运算，圆柱表示存储，胶囊表示终态；开放边界只表达真实作用域。主路径实线，反馈虚线，图例解释线型。不要把所有对象做成同样的卡片。

字体请求宋体和黑体；在本环境渲染使用Noto宋黑系以避免缺字。正文最小18px，组标题20—22px，禁止缩小字体来塞长句。以下是必须保留的短标签及坐标，按科学关系组织连线，线不得穿过无关标签。

- (36, 52)，21 px：输入证据
- (40, 90)，20 px：原始材料
- (40, 126)，18 px：题目／图片／实际步骤
- (322, 90)，20 px：学习上下文
- (322, 126)，18 px：偏好／有效学习记忆
- (604, 90)，20 px：来源快照
- (604, 126)，18 px：版本／指纹／记录引用
- (36, 222)，21 px：Python 智能计算
- (65, 295)，20 px：诊断与规划
- (65, 329)，18 px：实际步骤关联 / 任务阶段选择
- (333, 295)，20 px：工具执行
- (333, 329)，18 px：检索／判题／图形 / 结构校验
- (291, 444)，20 px：验证与反馈
- (291, 474)，18 px：符号核验覆盖范围内的结果
- (620, 222)，21 px：仓颉业务控制
- (627, 278)，21 px：身份与来源
- (627, 318)，18 px：租约／版本／预算
- (627, 376)，21 px：学习证据资格
- (627, 416)，18 px：当前步骤／重复应用
- (627, 478)，20 px：事务提交或拒绝
- (43, 615)，21 px：业务输出
- (178, 615)，21 px：错因回放 · 订正建议 · 训练 · 复习
- (43, 657)，18 px：MySQL 保存权威状态；学生的新作答进入下一轮证据组织。
- (450, 730)，18 px：实线：数据与提交路径     虚线：有界调整或新作答反馈

检查：主路径与上述构图一致；必须保留来源有效性和写入归属；不得添加性能、准确率、用户规模或手机安装记录。先检查全色图，再检查去标题灰度图的层次，最后检查Word实际宽度。几何构造源为build_refactor/render_figures.py的图02段，所有文本、路径及形状可在SVG中编辑。
