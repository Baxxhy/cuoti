## 已解决的语义问题

| 问题 | 核验依据 | 图中采用的准确含义 |
|---|---|---|
| 模型结果是否直接成为学习事实 | backend-cangjie/src/learning_task_worker.cj；backend-algorithms/mastery_tracker.py | Python仅计算提案；仓颉复核来源及任务资格，完成事务提交 |
| 是否为多个独立智能体协作 | backend-algorithms/learning_workflow.py的eced、confirm、student_action、aemt、arpp节点与路由 | 单协调工作流；学生、仓颉、Python是职责泳道，不是三个Agent |
| 发现错误是否等于定位首错 | backend-algorithms/error_diagnosis.py；diagnosis_alignment.py | 必须有实际步骤引用及有效前缀；前序证据不足时保留候选 |
| 提示、答案曝光与局部订正是否同样增加掌握 | backend-algorithms/mastery_tracker.py | 提示按0.35加权；答案曝光仅记录辅助学习；局部订正不作为完整作答更新 |
| 图中0.914和0.608是否实验准确率 | update_mastery函数实际复算 | 同先验0.35、非选择题、可靠正确事件、默认参数的规则演算，含学习转移；不是学生实验结果 |
| 是否在尚未修复时直接挑下一题 | backend-algorithms/learning_planner.py | 当前阶段完成且仍有时间/目标后，才筛选后续候选；图显示主要分支，完整条件见正文 |
| 检索和生成是否始终并行 | backend-algorithms/practice_generation.py | 检索先行，不足时受约束生成，进入共同候选核验 |
| 修改题干后历史结果如何处理 | backend-cangjie/schema/006_learning_tasks.sql；learning_task_worker.cj；learning_memory.cj | 旧快照保留为历史依据；新版本重新校验；图中的v1/v2是版本演化示意，不是完整数据库字段图 |
| 异步结果是否只在计算前检查 | backend-cangjie/src/learning_task_worker.cj | 计算结束后、业务写入前重新校验；主图突出版本、租约、取消和来源，其他条件由正文详述 |
| 检索索引是否替代业务数据权威 | 系统设计1.2节、仓颉检索协作与算法服务职责 | Python请求检索服务获得候选，仓颉按业务数据库验证原题及可用属性 |
