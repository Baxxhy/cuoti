# 《错题帮》项目文档证据核对表

> 2026-10-13 更新：用户已明确将当前请求模型名改为 `Qwen`。本文保留此前编写内容与历史验证记录，现行实现与验收状态请以 [本轮完善说明](2026-10-13-参赛完善说明.md) 为准；提交前需同步重新制作文档成品。

本表用于后续修改 Word 正文时快速区分“当前已实现”“原型验证结果”“正式评测目标”和“待替换结果”。它不是参赛正文附录，不需要随 Word 一并提交。

## 一、核心技术声明

| 文档声明 | 当前证据 | 写作边界 |
|---|---|---|
| 逻辑模型固定为 Qwen3.6-35B-A3B，模型请求经 API 池轮询 | `backend/app/providers/api_pool.py`、项目开发约定 | 不披露池内地址、密钥或条目内容 |
| 智能体生成不超过四步的公开行动计划 | `backend/app/services/agent_runtime.py` 中的计划 Schema 与执行逻辑 | 公开计划不是隐藏思维链 |
| 六类白名单工具 | Agent runtime 的 knowledge_search、step_alignment、visualization、rediagnose、answer_reveal、answer_check 注册与执行逻辑 | 不宣称任意工具自主执行；答案展示受用户意图约束 |
| 工具结果采用证据契约并区分 verified、partial、rejected | Agent runtime 的执行结果与证据核验逻辑 | 这是运行时可信机制，不等同于模型绝对正确 |
| 数学结论尽量使用 SymPy 验证 | 数学验证与诊断服务、后端测试 | 仅覆盖可形式化表达式，主观题仍需模型或人工复核 |
| 前端只消费 VisualizationSpec JSON | `frontend/src/visualizations/registry.ts`、`visualization-canvas.vue` | 当前为本地白名单校验函数与 Canvas，不写成 Zod/SVG |
| 原始上传图片不被清洁图覆盖 | 图像服务、资源模型与相关测试 | 派生图只能作为辅助证据 |
| 长期认知记忆由掌握、误区、更新与复习对象构成 | `MasteryState`、`MisconceptionState`、`CognitiveUpdate`、`ReviewPlan` 数据模型及服务 | 认知状态是随证据更新的估计，不是永久标签 |

## 四、可替换结果规则

- “已验证结果”只能填写当前报告、数据库快照或重新运行测试得到的数值。
- “目标指标”用于描述正式评测计划，可以写得有竞争力，但必须使用“目标”“计划”“拟达到”等措辞。
- “待替换结果”是后续实验数据入口；替换时同时填写样本规模、数据划分、基线、评测方法和置信区间。
- 正式结果更新后，修改 `错题帮项目文档源稿.md` 中带显式标记的段落，再运行 `build_project_document.py` 生成新的 Word。
- 不把 24/12/6/16 等固定样例结果包装为真实学生群体准确率或教学增益。

## 五、匿名与禁用项

- Word 中不得出现学校、学院、导师或真实成员姓名。
- 不出现旧产品代号、已移除的 OCR 方案、非当前后端框架、微服务、应用商店上线、离线大模型等与当前实现不符的旧表述。
- M3KE 许可未明确，CMM-Math/CMMU 的对外许可也应在提交前再次核验；未核验数据仅限本地研究验证，不随材料分发。
- 图位只保留图号、所需内容、建议形式和尺寸，后续替换为自制架构图、流程图、数据图或脱敏界面截图。
