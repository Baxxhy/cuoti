## 二、模板是否适用

Technical Writing确有模板。已读`references/document-types.md`、`references/structure-principles.md`、`references/review-rubric.md`与`assets/templates/explanation-doc.md`。其说明类模板为“概览—背景—机制—取舍—示例—相关概念”，可映射到参赛文档，而不是复制英文标题或保留占位符。该技能“一页一主题”等面向网页文档的默认建议不机械解释为Word每页只写一个小节；用户要求连续充分论述与合理层级优先。

Documentation Specialist确有12节arc42系统设计模板和简版C4模板。已读实际SDD模板，适合从中检查目标、约束、系统上下文、构件、运行、部署、数据、质量、风险和术语是否完整。它不是仓颉杯官方模板，不应将默认`DESIGN_DOC.md`输出位置、12章固定结构、Spring Boot例子、PCI/HIPAA等无关示例塞进本项目。其默认要求STE100语体包，且图形优先Mermaid；当前环境未安装该语体包，用户要求中文、Word和高质量PNG图，故仅参考结构，不声称完整执行了该插件流程。无需因此暂停工作或再安装一套语体插件。

Manuscript Writing提供修订清单，不提供Word转换工具或专用赛事封面。已完整读`references/revision-checklist.md`。应保留原稿，创建新文件；背景动机要有理论或可靠资料支持；算法输入、变量、步骤和边界要具体；技术名中文化不能改变计算含义。术语替换不能把既有BGE、Qdrant或SymPy变成团队自研底层模型。

riekelt审校入口要求先读其同仓库technical-writing及style/truth参考，还将所有破折号、SHA出现在正文等形式项列为硬性阻断。这些默认与本轮必要技术来源、原题减号和用户既有格式有冲突风险；不直接照搬其严重度定义。保留有事实边界的限定，不因“去AI”删掉数值来源和证据范围。

最终推荐最少组合为：Technical Writing负责技术表达，Manuscript Writing负责证据和论证，已授权anti-defensive-writing负责末轮语言精简。Documentation Specialist只提供结构检查参考。无需四项全部安装或强行串联。
