**位置：** 系统图5，`figures/07.png`中央四分区“技能、答案、年级、完整性”，检索和生成共同进入；正文4.3图后同样把两类合成一套检查。

### F03：08图输入与再次触发缺少有效连接

**位置：** 系统图6，`figures/08.png`。

**实际图片：** 左侧三项中只有“当前题目”连到“分析错因”；“学生新回答”和“已保存进度”没有进入计算的连线。底部“等待学生作答”返回线只指向“已保存进度”，没有说明新增回答才触发下一次调用。右侧“数学核验”和“提示与图解”也没有连接，只有“知识检索”接入双向工具线。

**为什么要改：** 正文明确说明新回答和保存进度共同参与本轮计算。图当前最关键的学生输入成为孤立框，循环箭头又没有动作条件，容易读成“等待结束后仅凭进度自动继续”。工具区也容易读成只有知识检索可调用。

**源码依据：** `backend-algorithms/learning_workflow.py:252`建立一轮START→诊断→学生动作→掌握→规划→END，待确认分支也到END；并无规划后自动回诊断的内部循环。`backend-cangjie/src/learning_tasks.cj`保存新学生动作并重新排队，工作器以本次动作和已保存检查点组织新调用。业务层才保存最终进度。

**修改建议：**

1. 用共同外框、括号或总线将左侧三项组合为“本轮输入”，总线进入分析；保持学生回答与保存进度可见。
2. 底部返回线接输入汇总，标注简短的“新回答触发”，不能仅接进度框。
3. 右侧三项用共同工具边界或总线接双向“调用与结果”线。可避免逐项交叉箭头。
4. 保留当前“分析错因→处理学生回答→符合条件时更新掌握→选择下一步→仓颉检查并保存”的正确方向。不要补回“规划直接回到诊断”的自动循环。

这属于数据流表达修复，不要求改变中央单协调器结构或既定配色。
