# 错题帮参赛完善计划（2026-10-13）

## 依据与目标

依据用户提供的《2026“仓颉杯”智能编程大赛通知》PDF，第 1、3—5 页，以及用户确认的“综合系统赛道、逐项检查”。评分重点是系统完整性与稳定性 25、架构与工程质量 25、智能技术深度 20、创新与应用价值 15、测试部署材料 15。目标是可运行、可复现、能接受随机输入与异常场景测试的学习闭环，不以页面数量或历史报告代替当前证据，不承诺奖项。

## 本轮交付

1. 修复真实使用阻断：重新识别任务等待、识别编辑生效、多选题提交、复习题干与选项完整展示、数学内容、失败恢复。
2. 保护学习数据：所有业务接口身份校验、实体归属、密码修改凭据、复习防重复计分、错题归档、题干修改后的分析失效及外键安全。
3. 增加错题学习档案：从 MySQL 读取录入、确认、诊断、辅导、练习、复习证据；提供真实进度和下一步入口、可复制摘要。区分“流程结束”“辅助完成”“独立验证”，不虚构掌握度。
4. 改进可复现检查：项目规定的后端/前端测试与 make verify；浏览器真实主流程检查；无远程 AI 的基础冒烟与需要外部 API 的实际链路验证明确分开。
5. 更新比赛交付说明：本轮实现、测试证据、第三方依赖、AI 辅助使用范围、演示步骤与仍需团队补齐的材料。

## 协作与范围

后端、前端和运行检查独立推进，主代理负责学习档案、整合和最终验收。沿用 Vue 3 / UniApp 现状、FastAPI、MySQL；不为仓颉加分临时重写技术栈，不引入 SQLite。AI 仍使用 ApiPoolProvider 和固定逻辑模型，结构化输出沿用 Pydantic，前端不执行模型脚本。保留用户现有 code.zip 和原始图片，不重置数据库。实现阶段完成后提交 Git。

## 验收

- 重要缺陷有行为回归证据，身份隔离与重复提交不能只靠源码字符串断言。
- 新档案没有学习记录时如实显示待完成，有记录时链接对应真实数据；不触发 AI 调用。
- 后端测试、前端测试、构建、代码检查、浏览器和本地冒烟结果单独记录；远程服务不可用时不得标记全链路通过。
- 文档中的历史数字不作为本轮验收结果；不得编造比赛成绩、学习提升幅度、用户规模、提交历史或演示效果。
