# 学习任务掌握度与复习写回迁移记录

日期：2026-11-17；版本：v1.0。

依据：`backend-cangjie/src/learning_task_mastery.cj` 的 `applyTaskAemt`，以及原认知计算与复习表结构。

本次实现 Python `task_evidence.apply_mastery`，在调用方持有题目、任务锁的事务中使用。仅接受当前步骤、实际提交文本和评分相互一致的独立作答或对照题证据；已展示答案的作答不刷新掌握时间，无提示记录的辅助作答不计入有效证据。对照题独立答对还必须通过曝光去重准入。

沿用 `cognitive_updates` 中任务与请求标识判重，复用已有 `cognition_update` 算法和掌握度、错因写回，不新增表或修改结构。辅助作答或答错安排一天后复习，独立答对安排三天后复习；存在待复习记录时不重复新增。算法计算遵守任务剩余预算，最多五秒并保留一秒事务余量。

单元测试覆盖独立正确、提示后正确、独立错误三条写回分支，以及已展示答案、重复记账、伪造作答的拒绝。启用本地 MySQL 与旧服务对照的 Python 后端全量回归：108 passed、12 skipped，用时 39.46 秒；未启用数据库的回归：66 passed、54 skipped。Ruff 与 Git diff 空白检查通过。新增写回分支本身采用模拟依赖单元测试，尚未通过完整真实任务验证。测试出现一条现有 Starlette/httpx 弃用提示。

尚未完成：该函数未接入完整任务结果提交与后台执行循环；本次不能视为学习任务端到端迁移成功。后续需整合旧工作流证据写回、任务图片、检查点和请求状态，并验证失败回滚、重试与完整真实任务。
