# 通用手写上传迁移与验收记录

日期：2026-11-17；版本：v1.0。

依据：`backend-cangjie/src/handwriting.cj` 的 `uploadHandwriting`，及 `practice_context.cj` 的 `practiceHandwritingContext`。复用现有 multipart 解析、图片标准化、原视觉识别算法与作答关联校验。

已接入 `POST /api/v1/answers/handwriting`，保持 `file`、`context_type`、`context_id`、`activity_id`、`mistake_id`、`mode` 等原请求字段和 `image_url`、`recognition` 响应。

- 辅导：必须是本人的当前活动，活动编号一致，原题没有变化或归档；选择题、讲解和教回不接受照片输入。
- 复习：必须是本人的待复习计划，选择题继续要求直接选择选项。
- 练习：检查本人错题与推荐关系，生成题另检查模式和来源版本；选择题不接受照片。

沿用 15 MB 上传限制和媒体签名。标准化照片继续使用原兼容路径 `uploads/answers/{user_id}/{kind}/{context_id}/handwriting-{编号}.jpg`。为落实保留原始上传文件的约定，额外保留同编号的 `.original.{格式}` 原文件，原始字节不重新编码，不增加前端字段要求。标准化文件写入失败时清理本次原文件；识别失败后保留两份照片，并返回原有“照片已保留”错误提示。

识别结果仅供学生核对，不自动代替作答。确认提交后，辅导、复习或练习接口继续使用已迁移的路径校验和 Pydantic 识别结构校验，判题仍根据实际提交答案执行。

MySQL 集成测试覆盖三类场景、其他用户拒绝、活动变化、选择题拒绝、原图字节保留、签名图片读取、识别结果随复习提交，以及模型失败后照片保留。普通用例模拟识别响应，图片标准化和提交结构校验使用原算法。

另新增可显式开启的真实视觉用例：`CUOTI_TEST_REAL_HANDWRITING_UPLOAD=1`。使用 PIL 绘制的合成笔画 `x=5`，通过实际 API 池调用视觉模型，读取识别结果后明确提交答案 `5`，复习判题正确。初轮真实测试 1 passed（10.25 秒），模型报告的 confidence 为 0.98。该数值是单次模型输出，不是识别准确率；合成笔画也不代表真实复杂手写样本已验收。

本次没有修改业务表结构、前端地址或旧服务。后续仍需可视化、导出组卷、语音、管理与系统接口迁移，以及统一部署和仓颉运行依赖移除；学习任务专用照片流程的更多真实样本验证继续保留为待办。

验证结果：启用本地 MySQL、旧服务对照及真实视觉用例的后端全量回归 132 passed、14 skipped（66.96 秒）。普通三场景及失败保留测试 1 passed（3.91 秒）。Ruff、格式和 Git diff 检查通过，保留既有 Starlette/httpx 弃用提示。
