# 复习与筛选业务迁移记录

日期：2026-11-17；版本：v1.0。

依据：`backend-cangjie/src/reviews.cj`，以及 `personal_learning.cj` 的 `searchReviewQuestions`、`savedReviewFilters`。

已迁移接口：

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | `/api/v1/reviews/today` | 中国本地日界限的到期复习、题目去重、来源版本与当前待反馈作答 |
| GET | `/api/v1/reviews/history` | 已完成难度反馈的复习记录 |
| POST | `/api/v1/reviews/{plan_id}/attempt` | 判题、请求幂等、替代旧待反馈作答 |
| POST | `/api/v1/reviews/{plan_id}/grade` | 接收难度反馈并安排下次复习 |
| GET | `/api/v1/reviews/search` | 按范围、学科及关键词搜索，每页 20 条 |
| GET、POST | `/api/v1/reviews/filters` | 查看与保存复习范围，最多 20 个 |
| DELETE | `/api/v1/reviews/filters/{filter_id}` | 删除本人保存的范围 |

继续沿用先作答、再反馈难度的两步流程。题目未分析、已归档、来源变更、已被替代的作答以及待核对的判题，不能完成复习计划。相同请求编号只可重放相同内容；当前有效作答可随今日列表恢复。今日题目隐藏原 `student_answer`，搜索投影不返回作答和标准答案，图片链接读取时重新签名。

间隔沿用原规则：again 为 1 天；hard 为正确 2 天、错误 1 天；good 为正确 7 天、错误 2 天；easy 为正确 15 天、错误 4 天。完成计划、更新作答反馈及创建下次计划在一个事务内保存，不重复完成同一计划。本接口保留原实现仅安排复习的行为，没有擅自追加认知写回。

保存筛选范围沿用同内容幂等、账号隔离及上限检查。修正方法不支持时的 `Allow` 响应，使新增迁移路由也列出完整允许方法；验证包含复习、变式题和学习任务自检。

MySQL 验证覆盖：判题与反馈、重复请求、内容冲突、替代旧作答、待核对拒绝反馈、错误作答间隔、重复完成拒绝、原题变化、历史记录、本人隔离、搜索分页与投影、今日去重、筛选范围重放、跨账号删除和 20 个上限。规则判题使用原算法，待核对情形使用受控结果。

旧服务对照：同数据的今日列表（含待反馈回执）及保存范围列表与 Python 一致。旧服务对 `/api/v1/reviews/search?q=复习检索&scope=today` 连续返回 HTTP 500，Python 搜索用例通过；因此没有宣称该搜索接口的线上响应对照通过，也未修改旧仓颉服务。Python 搜索按实际源码投影、筛选和分页规则验证。

本次没有修改数据库结构、前端地址或旧服务。后续继续迁移学习卷、可视化、语音、管理、导出、部署及其余仓颉依赖；通用复习手写照片上传仍待接入。

验证结果：启用本地 MySQL 和已有旧服务对照的后端全量回归 125 passed、14 skipped（51.80 秒）；随后补齐方法提示后的基础测试 18 passed（2.03 秒）。Ruff、格式及 Git diff 检查通过，保留既有 Starlette/httpx 弃用提示。
