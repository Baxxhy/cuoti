# 竞赛容器与离线镜像迁移验收记录

日期：2026-11-17；版本：v1.0。

本轮从 `1550e20` 开始迁移 Docker、容器启动、网关、离线资源收集和程序包组装。原有运行中的仓颉服务及原交付容器保持不变，本轮使用独立验收容器和数据卷。

## 已完成的部署改动

统一后端通过 `python -m cuoti_backend` 启动，复用原算法，不再运行仓颉程序或单独的 8012 算法进程。MySQL、BGE CPU 计算和 H5 网关沿用原部署形式；Qdrant 使用独立容器。

镜像构建资源包括 Python 后端、原算法、Python 依赖、MySQL 与客户端、原前端构建、Node、KaTeX 和 Chromium。公开配置模板单独复制；运行入口只收集 `entry.py`、`gateway.py`、`demo.sql`，排除 `.env`、真实模型池、备份及构建缓存。未收集仓颉 SDK、可执行文件、运行库或 `libzhiwei_mysql.so`。

完整模型镜像复用原交付镜像中的公共 CPU Python 环境、BGE 和语音模型缓存，不复制原业务程序、配置、密钥或学生数据。模型来源镜像 ID 已记录在构建上下文。两份依赖版本清单已按实际镜像环境重新生成，仅记录包名和版本。

原 `/data` 数据卷结构、`secrets.json`、图片目录、数据库名称和历史版本表保持兼容。启动时只对空业务库初始化；已有库缺少历史升级时默认拒绝启动，显式开启 `CUOTI_UPGRADE_DB=true` 后先做 SQL 备份再升级。更新脚本在替换已有容器前先停止服务并冷备份整个卷，校验 gzip 完整性，失败时恢复原容器；备份目录在停止前准备，完整文件权限为 0600。

网关保留认证、签名参数及下载响应，修复重复查询参数被折叠的问题。检查脚本实际执行容器内 Python 检查，校验后端身份为 `cuoti-python`。源码 ZIP 使用 Git 已跟踪文件，包含 Python 后端，不包含仓颉源目录和 SDK 安装脚本；基础资源测试不再依赖随包携带仓颉目录。

核心容器实际通过：H5 页面、注册登录、手动录题和查询、24 道演示题、练习与考试保存交卷、重复交卷幂等，以及知识、首页、复习和统计接口。

实际上传自生成作答图，原始字节哈希保持一致，签名链接可访问。数学题目 PDF、答案 PDF 和 Excel 均通过真实 Node/KaTeX/Chromium 生成并下载；PDF 正文及答案解析通过文本检查，Excel 公式图片及原文批注存在。

首次 PDF 失败定位为 Conda 的 `libffi.so.7` 指向 ABI 8，导致浏览器的 p11-kit 无法加载 ABI 7 符号。收集器已固定实际系统 ABI 7 与版本化终端库，并提供镜像内真实数学 PDF 检查入口。修复后的核心镜像通过检查，未手动修改的完整模型镜像也再次通过实际 PDF 导出。构建检查使用镜像自身文件系统，支持 Docker 客户端与守护进程不共享构建目录的环境。

从核心镜像切到完整镜像时，先对验收卷冷备份，再复用同一个卷。旧登录令牌继续有效，原错题、试卷和原图可读，原图哈希未变，演示题仍为 24 道，没有重复初始化。

真实 CPU BGE 生成 1024 维稠密向量及稀疏向量，重排模型正确区分测试相关文本；Qdrant 写入与查询通过。通过统一后端的计算入口完成真实稠密/稀疏融合检索及重排，返回 3 个命中、3 个排序结果和参考题。测试仅在独立检索容器创建验收索引。

使用现有模型配置对独立容器完成真实联网题目分析和错因诊断，MySQL 中保存的参考答案为 5，错因非空；自生成含错误作答过程的测试图经真实视觉模型完成上传、识别任务、题干及学生答案/步骤保存，原图哈希一致，随后人工修改并确认保存通过。该输入为测试图，不作为真实人类手写质量评测。

真实模型凭据仅临时注入验收容器的运行目录，未写入镜像、源码或 Git；源临时文件自动关闭删除，测试后移除容器内临时配置，后续重建容器不保留该配置。

在独立验收卷中，先 SQL 备份，再移除一个历史索引及版本记录模拟旧库：默认配置启动以退出码 1 拒绝升级；显式允许升级后自动再次备份、恢复索引及版本，并保留旧令牌和图片。没有对现有学生数据库进行该操作。
