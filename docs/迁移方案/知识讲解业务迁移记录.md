# 知识讲解业务迁移记录

日期：2026-11-17。版本：v1。基线：5a8ec50。

## 迁移内容

GET、POST /api/v1/knowledge/cards/{code}/lessons已接入Python，参照personal_learning.cj中的lessonCards、lessonSourceVersion、lessonVersionMatches及knowledgeLessons实际实现。

- GET返回本人最近10条讲解及source_current，不暴露其他学生历史。
- POST要求request_id，校验prompt及编号长度；同用户同编号同问题同来源重放已有结果，编号被用于其他问题时409。
- 基于当前知识卡及最多3张同学科前置卡调用既有knowledge_lesson算法，携带同一来源版本最近3次对话，复用其结构校验及来源引用检查。
- 来源指纹包含code、name、subject、content及依赖角色，排除导入时间与内部ID；兼容旧整卡指纹。知识变化后不把旧讲解静默标记有效，保存前再次比较来源版本。
- 讲解结果必须can_update_learning严格为false，不更新掌握度、认知状态或学习证据。单次计算沿原规则限制30秒，ComputeBridge增加局部timeout参数而不改变其他调用的默认超时。
- 继续写knowledge_lessons原表，保留原created_at文本返回形式；该表没有updated_at，使用其实际INSERT，不误用通用双时间字段写入器。没有改表或新增消息队列。

## 并发修复

两个相同请求可能同时完成模型计算。唯一索引(user_id,request_id)及ON DUPLICATE KEY保持单条保存，但初始测试发现可重复读快照使第二个请求在重复插入后读不到对方刚保存的记录。保存后的查询改为FOR UPDATE当前读，重复请求返回同一个id，冲突内容仍409。未宣称并发情况下模型只会调用一次。
