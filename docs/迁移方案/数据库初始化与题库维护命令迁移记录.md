# 数据库初始化与题库维护命令迁移记录

日期：2026-11-17；版本：v1.0。

本轮起点：`89d5c62`。依据原 `schema.cj`、`knowledge_seed.cj`、`question_bank_cli.cj` 及现有公开题源准备脚本，将部署和维护所需命令接入 Python；没有把应用启动改成自动建表或自动升级。

## 已实现

`python -m cuoti_backend.manage_db` 提供以下子命令：

| 子命令 | 用途 |
| --- | --- |
| `status` | 只读检查现有历史版本及缺失版本 |
| `backup` | 完整导出当前 MySQL 数据库 |
| `init` | 仅允许空数据库，执行原始建表及历史升级 |
| `upgrade` | 补齐缺失历史版本；已有全部版本时不执行写入 |
| `seed-knowledge` | 按原规则准备公开知识卡和前置关系，重复执行保留卡片 ID |

SQL 与公开知识卡资源纳入 `backend-python` 自身包资源，与原文件逐字节校验一致，执行时不读取仓颉目录。保留 `cangjie_schema_versions` 的表名及历史版本记录，以兼容现有数据；该历史命名不需要仓颉运行时。

已有数据库执行升级或知识卡准备前自动备份，备份失败立即停止维护。使用权限为 0600 的临时客户端配置文件传递密码，不将密码放入命令参数、日志或 Git；备份文件同样为 0600。备份保存在配置所属项目目录的 `.runtime/backups`，不提交仓库。

`python -m cuoti_backend.question_bank` 继续接受标准输入 JSON，提供 `import`、`review-format`、`cards`、`export` 和 `audit-export`。命令没有开放为 HTTP API。保留单批限制、内容指纹、质量标记、学科知识映射校验、格式隔离、旧核验记录和同内容重导入不得重新启用的规则。内容不变时不更新题目版本时间；错误映射或过期核验导致整批回滚。

公开题源适配器继续复用原实现。`scripts/question_bank.sh` 调用 Python 准备脚本；旧 `question_bank_cangjie.sh` 为兼容别名，也不再启动仓颉。批量导入前先备份，`--index-only` 不导入、不触发业务数据库备份。`make seed-knowledge` 和 `make import-questions` 已切到 Python。直接调用底层题库 JSON 命令前应先运行 `manage_db backup`；批量准备入口已自动执行该步骤。

补齐原准备脚本引用缺失的只读公式审计辅助文件，仍使用现有前端 `math.ts` 和 KaTeX 判断不可排版公式，没有新造识别或数学算法。真实前端排版器验证正常公式保留、非法公式进入核验；没有修改前端页面。
