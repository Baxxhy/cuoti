# 第二阶段实施指令

日期2026-11-16，版本v2。按用户最新要求简化数据库与工程流程，本版替代v1的隔离副本前置要求。第二阶段交付结果见《第二阶段完成与验证记录》。

目标是建立可运行、可测试的Python后端骨架，按学生个人项目规模组织代码。

1. 在 main 创建 backend-python，配置 FastAPI、Pydantic v2、SQLAlchemy 2.x、Alembic 和 PyMySQL。
2. 建立简单配置、日志、请求标识和应用启动入口，默认使用独立端口8003。
3. 优先读取已有 .env.cangjie 本地MySQL配置，支持环境变量覆盖，保护凭据。
4. 建立应用级Engine、独立Session与关闭逻辑，探测只执行SELECT。不为本阶段额外搭建隔离数据库或只读账号。需要改库时先备份。
5. 建立成功响应包装、中文detail错误、状态码和日期兼容基础。
6. 实现 /livez、/readyz，区分应用存活与数据库连接可用。暂无数据库时继续开发和模拟测试。
7. 通过导入和轻量适配复用现有数学工具、Pydantic类型及LangGraph入口，暂不执行真实AI流程。
8. 准备Alembic配置，暂不生成业务表模型、迁移版本或执行DDL。
9. 自动测试覆盖配置、协议、异常、HTTP边界、Session生命周期、算法复用，已有MySQL可用时追加真实只读探测。
10. 检查原业务、算法、前端与部署入口的改动范围，记录真实结果，提交并推送main，阶段完成后停止。

本阶段不迁移完整用户、错题、复习等业务，不切换前端API地址，不删除仓颉代码。后续按业务逐项迁移时再补充相应事务、数据兼容与回归用例。
