# 第二阶段实施指令

日期 2026-11-16，版本 v1。源码基线为 origin/main 的 1e116f574a88bb009b618218df23f679adc7a5fe 及本次纯文档校准提交。此文档是后续实施任务说明，本轮尚未执行。

## 目标与范围

创建 backend-python，建立 FastAPI、Pydantic v2、SQLAlchemy 2.x、Alembic 和 MySQL 的可测试骨架。复用 backend-algorithms 的计算模块。保持原运行入口，独立启动新服务验证，不切换前端。

本阶段交付限于配置、日志、数据库连接、响应与异常兼容、健康接口、算法导入适配和自动化测试。账号、错题、学习任务等完整业务留到后续阶段。保留全部仓颉代码，保护现有业务数据库与媒体。

## 实施顺序及交付

1. 确认当前 main 与 origin/main 一致，核对未提交改动归属。直接在 main 工作。检查 Python 版本、已有算法依赖与目标依赖兼容，建立 backend-python/pyproject.toml、可复现依赖约束及独立开发环境。FastAPI、Pydantic v2、SQLAlchemy 2.x、Alembic 和 PyMySQL 作为明确依赖，禁止顺带升级原算法依赖。
2. 建立 app/main.py 工厂和 app/api、app/schemas、app/infrastructure、app/algorithms 等目录。按实际需要创建模块，暂不生成全部业务空壳。
3. 建立 Pydantic v2 配置模型，配置应用标识、独立监听端口、数据库地址、连接池、超时、日志等级及算法配置。数据库凭据使用 SecretStr 等方式保护，配置错误在启动时明确报告。保留旧 CANGJIE_* 配置作为后续适配来源，骨架默认禁止连接现有业务库，测试使用专门配置。
4. 建立结构化日志及 request_id 中间件。记录请求路径、状态、耗时和错误分类，禁止记录密码、令牌、API密钥、原始请求体与数据库连接字符串。异常日志不得泄漏学生原始资料。
5. 建立进程级 SQLAlchemy Engine、请求级 Session 依赖和关闭逻辑，设置 utf8mb4、连接超时及 pool_pre_ping。连接在使用时建立，导入模块不触发数据库访问。Session 不跨请求、线程或 Agent 调用共享。骨架仅执行 SELECT 1 和必要只读元数据查询，不执行 create_all、建表、DDL、stamp 或数据写入。
6. 建立请求响应兼容模型。成功格式为 `{success:true,data:...,error:null,request_id:"..."}`，错误为 `{detail:"..."}`。保留 null、布尔、整数、浮点、JSON 和日期的实际类型。健康接口依照下面的独立约定，不套业务 envelope。
7. 建立统一异常处理，业务错误保留状态码和中文消息，输入对象错误为422，数据库不可用为503，未知错误为500并返回通用信息。405 的 Allow、413大小限制、未知路径404、尾斜杠行为均建立测试。请求参数细节以旧接口契约为准，骨架先验证公共机制，不注册伪业务接口。
8. 实现 GET /livez，无数据库访问，返回 `{service:"cuoti-python",status:"alive",version:"..."}`。实现 GET /readyz，成功执行只读探测后返回 `{database:"mysql",status:"database_ready",ai:"not_connected"}`，连接失败或超时返回503及 `{status:"database_unavailable"}`。两者非GET返回405。此时 readyz 表示连接可用，尚未证明所有业务表结构、模型或向量检索已就绪，完整切换前再增加结构版本核对。
9. 引入 backend-algorithms 已有模块，优先通过可编辑安装复用，核对 learning_core 与顶层计算模块的包配置。建立轻量适配器，复用确定性的数学函数及已有 Pydantic 类型，保持原函数输入输出，不复制算法。LangGraph 图继续通过既有 build_learning_graph/run_learning_workflow 入口导入，导入测试不执行模型、图流程或数据库写入。Qdrant/BGE 和模型池采用可注入客户端，默认不联网、不加载模型。
10. 准备隔离 MySQL 副本并验证。先由授权环境提供已有备份或准备独立数据库，记录来源、恢复方式、目标主机/端口/库名和只读账号。恢复过程只能操作隔离实例，绝不从测试启动逻辑自动创建或覆盖业务库。可选库名前缀为 cuoti_migration_test_，实际名称在测试配置明确指定。连接检查通过后，以仅含 SELECT 权限的账号运行骨架验证，防止误写。
11. 建立 Alembic 目录、配置与 env.py，但不执行数据库迁移或版本标记。元数据与现有51表/实存历史差异的建模安排留给业务迁移阶段，不能用空元数据生成删除历史表的迁移。
12. 运行自动化测试与独立端口健康检查，记录真实结果，再提交并推送 origin/main。阶段完成后停止，等待下一阶段指令。

## 自动化验证矩阵

| 用例 | 条件和操作 | 必须通过的结果 |
|---|---|---|
| 配置校验 | 缺少数据库配置、无效端口、日志打印配置 | 明确拒绝错误值，日志没有秘密 |
| 应用导入 | 阻断外网与数据库，导入应用、算法和LangGraph构建入口 | 不连接外部服务，不加载本地模型 |
| liveness | 数据库不可用时请求 /livez | 200，service/status 正确 |
| readiness成功 | 隔离副本只读账号执行探测 | 200，执行语句均为只读 |
| readiness失败 | 错误密码、不可达地址或超时 | 有界超时，503，无凭据泄漏 |
| 响应协议 | 使用测试专用路由构造成功与业务错误 | envelope、request_id、类型与detail匹配 |
| 异常映射 | 注入输入验证、数据库异常、普通异常 | 422/503/500，安全中文提示 |
| HTTP边界 | 错误方法、未知路径、尾斜杠、请求超限 | 405/404/明确尾斜杠策略/413，Allow正确 |
| Session生命周期 | 多请求并发、异常和关闭 | Session隔离，资源释放，无悬挂连接 |
| 算法复用 | 调用确定性数学函数、校验Pydantic模型 | 结果与原模块一致，无重复实现 |
| 安全范围 | 查看测试日志、SQL记录、目标配置 | 仅隔离副本，无业务库写入、无真实模型请求 |

单元测试使用 FastAPI TestClient/httpx 与注入的模拟依赖。数据库集成测试使用独立标记，例如 pytest -m mysql_readonly，显式传入隔离库配置后才运行。实际命令应随新骨架的项目配置一并交付，不能继续调用已删除的 make verify、scripts/verify_cangjie.sh 或前端 npm test。

当前 main 的已有回归命令可由已安装 pytest 的环境执行 `PYTHONPATH=backend-algorithms python -m pytest -q backend-algorithms/tests`。这只覆盖当前四个算法测试，不能替代骨架测试。

## 阶段验收与回退

验收需要独立服务可启动、上述测试全部有执行记录、隔离副本连接与只读查询通过、现有四个算法测试通过、现有前端API地址与原服务运行入口无变化。Git diff 应仅包含 backend-python 与必要的开发依赖、测试说明或骨架启动入口，不出现仓颉业务新增或算法重写。

若缺少隔离数据库，可继续完成模拟测试和配置准备，但必须将真实MySQL验证标记为待完成，不宣布阶段通过。失败时停止新服务，保留原运行系统，修复骨架配置或测试即可，不修改或降级业务数据库。
