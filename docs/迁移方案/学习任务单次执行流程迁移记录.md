# 学习任务单次执行流程迁移记录

日期：2026-11-17；版本：v1.0。

源码依据：`backend-cangjie/src/learning_task_worker.cj` 的 `runLearningTask`、`taskFailure`，以及 `learning_task_images.cj` 的 `taskImageComputeAction`。

已实现 `task_worker.run_task`：在事务中领取租约和准备上下文；在事务外调用原 `learning_task` 算法；提交前重新锁定题目和任务，复核租约、题目版本、不可变来源与学习上下文；将计算结果交给结果事务保存。沿用 45 秒任务预算，计算最多 40 秒，预留提交时间；未新增数据库结构或重新实现教学算法。

手写输入只从同一任务、同一来源版本的原图读取，校验 SHA-256 后临时编码给算法，不把编码写回任务。错误只记录阶段、数据库错误号或 API 状态，避免将供应商错误内容、凭据和学生文本记入日志。失败保存只允许当前有效租约执行，并保留重试入口与已有照片；照片识别失败还可改用文字。

本地 MySQL 集成验证：正常执行保存结果；模拟算法不可用后记录 `compute_api_503` 并释放租约；计算期间替换租约后旧执行者放弃保存，不覆盖新租约。队列状态在领取事务内设置，避免测试任务被正在运行的旧服务领取。图片单元测试验证原始字节绑定、篡改拒绝和跨任务版本拒绝。

上述新执行测试使用模拟算法响应，不能视为真实模型端到端验收。尚未接入应用生命周期中的持续轮询，也未开放任务 API；后续将一并接通任务创建、动作提交、查询和照片上传，再验证完整流程。

本次验证结果：启用本地 MySQL 和旧服务对照的后端全量测试 109 passed、12 skipped（38.65 秒）；针对执行和图片测试 2 passed。Ruff 与 Git diff 检查通过。存在一条既有 Starlette/httpx 弃用提示。
