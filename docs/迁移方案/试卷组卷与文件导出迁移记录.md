# 试卷组卷与文件导出迁移记录

日期：2026-11-17；版本：v1.0。

源码依据：本轮起点 `129bec6` 的 `papers.cj`、`paper_validation.cj`、`paper_candidates.cj`、`paper_exports.cj`。算法继续调用 `backend-algorithms/paper_export_compute.py` 与原 PDF、Excel 排版工具，没有重新实现算法。

## 接口与业务

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | `/api/v1/papers/candidates` | 本人的未归档错题候选，支持学科、知识点、错因、掌握度和复习状态筛选 |
| GET | `/api/v1/papers` | 本人的试卷列表 |
| POST | `/api/v1/papers` | 按指定题目或筛选结果创建试卷，保留默认分值及逐题覆盖 |
| GET | `/api/v1/papers/{paper_id}` | 试卷、题目、分析就绪状态和导出记录 |
| PATCH | `/api/v1/papers/{paper_id}` | 修改标题、筛选条件和题目顺序及分值 |
| DELETE | `/api/v1/papers/{paper_id}` | 删除试卷及关联数据库记录；保留原导出文件的旧行为 |
| POST | `/api/v1/papers/{paper_id}/export` | 题目 PDF、答案 PDF、Excel |
| GET | `/api/v1/papers/{paper_id}/download` | 下载最近生成的指定类型文件 |

保留原选题去重顺序、知识点文本匹配、最新错因、首个匹配掌握度和复习状态规则。`due_review` 延续旧实现，表示最新复习计划处于 `pending`，不额外添加日期到期条件。显式选择题目仍按原规则允许本人的归档题目。候选的补充知识点来自最早分析，答案及错因来自最新记录，未擅自统一这些历史行为。

试卷继续使用现有 `papers`、`paper_items`、`export_jobs`；没有数据库结构变更。修改题目失败时事务回滚，保留修改前内容。试卷与题目均校验本人归属；下载和签名媒体访问沿用原权限。

答案 PDF 在缺少答案或解析时返回 409。生成文件检查 Base64、非空、64 MB 上限及 SHA-256。文件写入后记录保存失败时，删除本次新文件，不删除历史文件。导出下载保留二进制附件响应及 `{detail}` 错误结构。

## 实际验证

- 启用本地 MySQL 和旧服务对照，试卷专项测试 **2 passed**（17.34 秒）。真实生成并下载题目 PDF、答案 PDF、Excel，检查附件与签名内容一致、Excel 正文、跨用户拒绝、缺失分析、无效格式、文件哈希错误及记录写入失败清理。
- 同数据试卷列表、候选和详情与旧服务一致；比较签名链接时忽略随读取时间变化的签名查询参数。
- 额外通过实际 KaTeX/Chromium 排版生成含 `$3x+2=17$` 的题目及答案 PDF，并用 `pdftotext` 检查题干、分值与答案解析的显示区分。未把这项文本检查描述为人工视觉验收。
- 后端全量回归 **138 passed、15 skipped**（70.81 秒）。跳过的可选真实模型等用例没有计为通过；保留既有 Starlette/httpx 弃用提示。
- Ruff 检查和格式检查通过。

最初数学 PDF 失败的原因是当前工作目录缺少前端排版依赖。已按现有 `pnpm-lock.yaml` 安装依赖并复用已有 Chromium 及其动态库，保持真实数学排版，没有改成纯文字回退。部署必须包含前端排版依赖、Node、Chromium 和所需动态库；本地测试通过 `ZHIWEI_PDF_CHROMIUM` 与 `LD_LIBRARY_PATH` 指定已有浏览器环境。没有改变前端页面或 API 地址。

下一步核对全部路由及命令行能力，迁移本地启动、初始化和竞赛部署入口，验证后再移除仓颉运行依赖。当前旧服务仍保持运行，本轮完成不代表全部迁移结束。
