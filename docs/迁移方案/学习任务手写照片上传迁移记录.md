# 学习任务手写照片上传迁移记录

日期：2026-11-17；版本：v1.0。

依据：`backend-cangjie/src/learning_task_images.cj` 的 `uploadTaskHandwriting`，复用已迁移的 multipart 解析、原图存储、学习任务算法输入及识别结果保存能力。

已迁移 `POST /api/v1/learning-tasks/{id}/handwriting`，成功状态 202。沿用表单字段 `request_id`、`version`、`step_id`、`input_fingerprint` 和单个 `file`；只允许学生上传本人的当前任务照片。维持 15 MB 图片限制和 JPEG、PNG、WEBP 文件头检查。照片完整写入原路径格式 `uploads/answers/{user_id}/learning_task/{task_id}/{image_id}.{extension}`，记录 SHA-256，不重新编码原图。

沿用请求内容摘要，重复上传相同照片和步骤不新增记录，复用请求编号更换照片或步骤返回 409。仅当前可输入文字的步骤接受照片；校验来源指纹、版本、步骤和执行上限后，在同一事务中保存图片关联和识别动作，再把任务排队。事务失败时删除本次成功写入的新文件，保留已有文件。原有普通错题上传行为保持不变，multipart 解析仅新增可选的字段返回模式。

现有执行器读取原图并校验哈希后调用原算法，结果等待学生核对；提交答案时必须携带当前图片编号并明确确认，识别结果不会自动成为学生的最终答案。任务公开视图和历史继续使用原媒体签名及账号隔离规则。

MySQL 集成测试覆盖：他人上传拒绝、未知字段、无效格式、无效版本、过期步骤、首次上传、重复上传、更换内容冲突、原图字节校验、模拟识别结果保存、签名图片访问和跨账号限制、确认前后提交，以及数据库保存失败时新文件与数据库记录回滚。测试用准备状态模拟避免旧执行器领取测试任务，OCR 结果为模拟数据，不代表真实模型验收通过。

剩余：题目学习旅程汇总、启用 Python 持续执行器后的真实模型完整任务验收，以及剩余业务、部署和仓颉依赖的移除。前端地址和旧服务本次保持原配置。

验证结果：启用本地 MySQL 和旧服务对照的后端全量回归 114 passed、12 skipped（43.34 秒）；上传确认与失败清理测试 1 passed（3.74 秒）。Ruff、格式和 Git diff 检查通过，保留既有 Starlette/httpx 弃用提示。
