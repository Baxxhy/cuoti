# 本地启动与配置切换迁移记录

日期：2026-11-17；版本：v1.0。

源码起点：`7c2eadb`。本轮迁移源码开发入口、配置读取、健康检查及本地管理员命令。竞赛容器和离线程序包不在本轮完成范围，不能使用本记录宣称全部部署已迁移。

## 现在如何启动

| 入口 | 当前行为 |
| --- | --- |
| `make install` | 安装原算法包、统一 Python 后端及开发依赖，再安装前端依赖 |
| `make backend` | 启动 Python 业务后端，不编译仓颉 |
| `make dev` | 启动统一 Python 后端及原前端；算法在后端进程中复用，不单独启动 8012 |
| `make check` | 只读检查 Python 身份、MySQL 历史版本和所需表字段、前端页面 |
| `make setup-local` | 为全新环境准备独立 MySQL 库、账号及 `.env.python`，通过 Python 初始化和准备知识卡 |
| `bash scripts/local_user.sh` | 通过 Python 创建或检查管理员，无需编译器 |
| `make algorithms` | 可选的独立内部算法进程；普通统一后端启动不需要此进程 |

统一后端默认端口 8002，前端 5175；显式使用 `CUOTI_PORT`、`ZHIWEI_FRONTEND_PORT` 可以并行验证。前端代理由启动器设置 `ZHIWEI_BACKEND_URL`，没有改前端页面或 API 路径。

启动器先检查端口及数据库结构，不运行建表、升级或模型探测。已有端口被占用时停止启动，不接管或杀死旧服务。前后端子进程使用本次独立进程组；任一服务退出时清理另一服务，收到停止信号时只停止本次启动的进程。

学习任务执行器在正常启动入口默认启用，显式 `CUOTI_LEARNING_TASK_WORKER_ENABLED=false` 仍可关闭；直接构造 FastAPI 应用仍默认关闭，便于对照测试。单套后端自己完成识别及学习任务执行，不为默认运行再创建第二个算法服务。

## 配置和数据兼容

优先选择 `.env.python`，缺少时读取 `.env.cangjie`，`CUOTI_ENV_FILE` 可以指定已有配置。两种配置使用同一解析器，不通过执行 Shell 来加载默认业务后端配置。同名环境变量优先于文件，新的 `CUOTI_*` 配置优先于相应兼容旧项。

保留旧数据库连接信息、原认证与算法密钥，以及旧后台端口。读取原 `.runtime/cangjie-auth-secret`、`.runtime/cangjie-algorithm-secret`，不自动替换已有密钥；仅缺失时以文件锁生成持久的新密钥，文件权限为 0600，不输出密钥值。

已有默认 `backend-cangjie/media` 目录时继续使用，旧的相对 `CANGJIE_MEDIA_ROOT` 也保持原相对位置。新配置的相对 `CUOTI_MEDIA_ROOT` 以项目根目录解析，新项目默认 `media`；没有搬移、重写或删除历史图片。旧目录名称是存储路径兼容，不需要仓颉 SDK 或运行时。

算法服务及 BGE/Qdrant 适配器增加 `CUOTI_*` 配置名，仍兼容原 `CANGJIE_*`。直接 `python -m cuoti_backend` 会先加载配置，再导入算法模块，避免 Qdrant 配置和服务端模型凭据环境变量在模块初始化时漏读。原算法实现、模型接口及前端 VisualizationSpec 规则没有更换。

`/readyz` 不再仅执行 `SELECT 1`：只读检查 13 个历史版本及实际使用的表字段；缺版本、表或字段返回 503，多出的历史表允许保留。该检查不执行 DDL。

全新初始化拒绝已有配置、同名库或账号；显式指定现有 `CUOTI_ENV_FILE` 时同样拒绝初始化。本地管理员命令保留 `--role admin`、`--check` 和 `--password-stdin`，先检查邮箱再收集密码，不覆盖现有密码，也不提升学生身份。

## 剩余工作与回退

本轮没有数据库结构变更；源码启动默认入口已切换，但竞赛镜像、打包脚本、容器启动与已有程序包仍使用旧实现，需要继续迁移并完成独立部署验证。Alembic 后续版本管理及最终仓颉运行依赖清理也尚未完成。

回退当前源码启动入口可以撤销本轮提交，保留现有 `.env.cangjie` 和密钥后使用旧启动脚本；数据库、账号与原图不需要因本轮入口调整而重建。切换时先停止本次 Python 服务，再启动对照服务，避免同一端口冲突及两套执行器同时处理工作流。不要将删除数据库、媒体或其他工作树作为回退步骤。
