# 仓颉主后端迁移

日期：2026-10-15。用户授权：重写后端业务、接口与数据库交互为仓颉，并验证；Python 保留 AI 与专业算法服务。

用户补充：保留现有完整 Python 版本，新开发独立仓颉版本。原 `backend/`、启动命令与验证入口保留；新版本位于 `backend-cangjie/`，使用独立端口和独立开发/测试数据库，避免两个版本同时改写现有用户数据。

当前范围以学生学习和作业功能可运行为准，不新增运维、部署或性能专项；清理已确认没有调用和业务用途的入口。

## 完成定义

- 前端既有 API 契约保留，全部业务路由由仓颉实现，不以代理旧 FastAPI 作为完成。
- 仓颉负责鉴权、权限、MySQL 业务读写、任务状态、教学流程、教师/家长/管理员业务。
- Python 只承担模型池、Pydantic 输出校验、OpenCV、SymPy、BGE 检索、文档生成等专业能力；不作为业务数据库写入的替身。
- 保留现有 MySQL 数据、迁移历史、密码/会话兼容、原图与签名资源隔离。禁止 SQLite 回退，禁止输出 API 池凭据。
- 新增独立仓颉本地启动入口，验证前端业务流程、MySQL 读写及算法服务集成；原有 `make verify` 保留并新增 `make verify-cangjie` 覆盖新主后端，保留 Python 算法测试。
- 分阶段提交 Git，最终工作区干净。编译或少量单元测试通过不代表迁移完成。

## 实施顺序

1. 工具链与契约：固定官方 SDK，建立仓颉工程，枚举现有路由与数据表，验证 HTTP/JSON/MySQL。
2. 基础设施：配置、错误封装、数据库连接与事务、鉴权与签名资源访问，验证旧凭据兼容与数据隔离。
3. 基础业务：账户、题目 CRUD、知识库、班级与任务、试卷、家长与管理接口。
4. 算法边界：抽离 Python 内部计算服务，保留 ApiPoolProvider/Qwen/Pydantic；仓颉组织识别、诊断、评分与导出任务。
5. 学习闭环：教学阶段、讲回与迁移训练、掌握度、复习、教师复核；验证必要的失败提示、刷新和恢复。
6. 双版本验收：原 Python 启动方式保留，新增仓颉版入口；全量契约和真实 MySQL 验证、前后端测试、完整检查、两版运行说明和提交。

- `routes.json` 是从当前 Python AST 提取的 103 条路由初始清单，尚需逐项确认路由前缀、响应、权限与副作用；所有条目初始为 pending。
- 每个迁移模块包含仓颉行为测试。数据库测试使用独立测试数据并清理，不清空用户数据库。
- 编译器、驱动与网络依赖必须实际运行验证；涉及并发、事务、认证的行为不能用源码字符串检查代替。
- 已有 Python 行为作为兼容参考；发现安全缺陷时修复并增加回归，不复制缺陷。

### 2026-10-15：签名文件访问

- 仓颉原生接入 `/uploads/*` 和 `/reports/*` 的 GET/HEAD，签名校验在文件打开和缓存校验之前执行。默认独立 `backend-cangjie/media/`，可显式设置 `CANGJIE_MEDIA_ROOT`；不读取原版文件目录，也不通过 Python 提供文件服务。

- 支持 HEAD、单段 Range、If-Range、ETag/If-None-Match；多段 Range 回退完整 200。SDK 1.0.5 对 HEAD 已知空响应体与非零 Content-Length 的检查导致 500，已使用未知长度的空输入流兼容，真实 HEAD 验证通过。
- HTTP 验证中文/空格路径、签名过期/篡改/超长有效期、路径越界、符号链接、FIFO、空文件、范围边界、大文件、文件更新后 ETag 变化和并发中途断开后无文件句柄遗留。详情接口返回的实际签名链接也下载验证通过。
- `make verify-cangjie` 通过全部原生和 HTTP/MySQL 回归；数据库未配置时资源服务仍能独立验证。原 Python 源码、上传文件和数据库未变。资源挂载不计入 103 条业务 API，整体迁移保持未完成。
