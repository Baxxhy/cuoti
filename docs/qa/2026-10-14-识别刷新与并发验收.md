# 识别刷新与并发验收

本轮在本机 HTTPS 发布版、FastAPI 与真实 MySQL 上继续验收。最终完整检查通过：293 项后端、67 项前端、21 个浏览器场景，并通过新增的真实 MySQL 并发检查。Ruff、TypeScript、H5 构建、代码格式和 46 个后端源文件类型检查通过。

## 发现与修复

| 复现的问题 | 修复与证据 |
|---|---|
| 裁剪识别中刷新，页面丢失原任务并重新显示“开始识别” | 题目详情返回当前识别任务与已保存范围；裁剪页恢复并查询原任务。浏览器刷新、轮询失败、恢复网络后仅有一次裁剪提交 |
| 重复裁剪创建两个任务，改变范围会覆盖正在识别的图片 | 同范围继续已有任务；不同范围在识别结束前返回 409。题目写锁序列化创建，原图与裁剪图摘要保持不变 |
| 归档题目的旧裁剪页能重新启动识别 | 所有识别启动/重试入口检查归档状态；旧页面显示返回错题本。相关后端行为测试通过 |
| 重新识别及旧失败任务重试能与新任务并存 | 统一检查当前任务并复用，不额外安排处理。旧任务不会被误改为正在处理 |
| 首版任务查询锁在两道不同题并发时触发 MySQL 1213 | 在真实事务交错中复现。现在结束只读预检事务后锁定题目，以普通读取查询当前任务，避免锁住空任务范围；两道题均成功创建任务 |

裁剪范围统一存为归一化边界，页面恢复时转换为位置与宽高。没有范围记录的旧任务继续查询，不显示猜测的裁剪框。图片准备完成但仍需要框选时回到框选操作，不直接展示空白核对页。

## 真实事务验证

`make verify-recognition-concurrency` 已接入 `make verify-local`，因此也是完整检查的一部分。

- 同题两个并发提交：一个任务、一次处理安排，两次返回同一个任务 ID。
- 不同题的两个事务在题目锁定后交错：两道题都创建成功，各安排一次处理，没有数据库锁冲突。
- 识别中改变范围：返回 409，已有裁剪图不变。
- 当前任务和裁剪范围可从题目详情恢复，原始图片摘要相同。

该检查调用真实 MySQL 和实际后端处理函数，捕获处理安排但不执行 AI；创建的独立临时账号、题目、任务和图片在结束后清理，不改动已有用户。

## 模型与浏览器实测

独立题目的真实 Qwen 识别完成，任务状态为 `completed`，页面显示方程内容，原图摘要不变。实际服务日志中仅有一次该任务的重试提交。

另外在读取这个已完成结果时阻断网络响应：页面显示重试入口，恢复网络后结果出现；再次刷新仍显示同一结果，没有新增识别重试或页面运行错误。

计算进行中的刷新与轮询故障使用公开固定状态和受控失败响应进行浏览器回归；已完成真实结果的网络中断恢复单独验证。两类证据分别记录，不把固定响应当作真实模型调用。
