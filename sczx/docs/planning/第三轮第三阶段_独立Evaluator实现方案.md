# 独立Evaluator实现方案

2026-11-16 / design-v1。实现方案，尚无运行中的新Evaluator。

## 角色和数据边界

盲化导出器读取生成记录，去除组名、文件路径、run名称、组提示词、预期策略、rater_reference、独立题标准答案、评分金标、检索算法分数、模型身份及项目决策对象。生成随机opaque ID，只把题目/原答/自述、原始相关证据与历史、学科/年级、待评响应、实际引文和公共知识依据传给Evaluator；输出内显式A/B/C/D标签仅在边界位置去除并另留redaction_map，正文不改写，原件不覆盖。不能因为语义风格可能暴露方法而声称绝对双盲。

Evaluator包括确定性规则和独立LLM两条路径，都不得读取组别、组提示词、预期策略标签或标准答案。规则可以从公开题干推导数学关系、校验版本身份/年级范围/可见历史，不硬编码当前题的gold答案。冻结测试标签仅存于外部可靠性测试器，比较Evaluator输出是否符合测试断言，不进入生产Evaluator请求。统计器只在评价结果锁定后关联组键，组键不反向暴露给Evaluator。此划分解决“使用冻结标签”与“评价器不读标准答案”的要求。

白名单contract见stage3_design/contracts.json。导出采用重新构造对象，不能只pop几个黑名单字段；递归拒绝嵌套禁用字段，验证严格schema，发现泄漏记录泄漏而不静默继续。可靠性测试使用金丝雀秘密值验证日志/网络payload无禁用内容，不把自报“未读取”当测试。

公共知识和来源账本所有组可供评价的内容一致，但不能包含当前题的标准解答、预期策略或描述性评分提示；引用核对只取被引用片段及必要上下文，不喂完整检索排序和项目审核结论。许可状态与可用范围以独立source_registry呈现，不给“C选中”等方法标签。允许模型提出与冻结预期不同但有据的策略。

## 自动指标

|旧指标|自动替代量|计算与边界|
|---|---|---|
|困难识别|证据扎根率、无依据诊断率、适当保留不确定性率|抽取判断及其证据offset，规则校验引用存在；独立LLM判断证据是否足够支持，不等同真实认知诊断准确率|
|策略适切性|自动适切性代理0/1/2与可执行动作覆盖|0明显违背条件/干预，1相关但不充分，2有依据可执行；不比对expected_strategy，不以关键词选中foundation判优|
|内容正确|可证事实/数学检查覆盖、已证错误率、LLM内容风险代理|确定性求解只支持可解析范围；开放学科未知必须unknown，不能把“没查出错”当全正确|
|引用质量|身份有效率、学科/年级/边界一致率、引文语义支持代理|分别验证来源版本/许可、有效范围及建议是否受片段支持；A无引用为not_applicable，不能自动判教学失败|
|差异化|同题不同历史的依据一致变化率与错误干预代理|成对盲化、两种呈现顺序；比较动作是否随有效历史变化，措辞变化不计收益；无效历史不应改变难度/诊断|
|独立新题表现|真实学习收益不可测量；可自动检验题目独立性和题目可判定性|没有真实作答即not_measurable，禁止让LLM扮学生后把得分称作学习提升|

响应schema：opaque_id、status、各metric的value/scale/measurement_type、coverage、evidence_offsets、public_source_ids、reason、error_types、uncertainty、evaluator_model_requested/returned、prompt_sha、request_sha、raw_output_sha、latency、attempts。measurement_type限定deterministic_verified、llm_proxy、not_applicable、unknown、not_measurable。LLM自报confidence仅为自报字段，不作为校准过的概率。

原始请求、原始回答、解析结果和逐条依据只增存储。规则与LLM分数分列，不以加权总分掩盖严重错误；严重错误/来源不存在等确定性否决不被LLM好评覆盖。规则与LLM冲突、两种顺序分数不一致或公共依据不足时，输出evaluation_uncertain，进入固定预算第二个独立判别配置复核；最多2次评价调用，仍不一致保留unknown，自动结束，无人工仲裁。第二配置未部署时不伪造冗余评价，直接unknown/configuration_blocked。

独立LLM用独立模型系列和无状态会话，不能读取生成模型思维链或复用生成会话。模型提供者、精确版本、参数及提示词必须在正式运行前配置冻结；缺失则无人值守流程在配置门槛自动停止。本轮没有选择未经验证的现成服务，未发生模型调用。

## 实施顺序

先实现严格DTO、隔离进程、文件白名单和payload泄漏测试；再实现来源/范围/数学确定性规则；再接独立LLM的结构化代理指标及证据offset校验；最后做冲突合并、可靠性门槛与统计导出。复用现有解析与适用规则的纯函数，但不连接业务数据库，不复制业务经验库。实现后才允许宣称Evaluator可靠性测试通过。
