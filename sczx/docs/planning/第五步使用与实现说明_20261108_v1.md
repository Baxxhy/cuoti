# 第五步使用与实现说明

日期 2026-11-08　版本 v1

状态：实施中。现有环境已验证文本指导、图文/OCR、Embedding 和 LLM 语义重排；ASR、TTS 仍待可用配置和真实验收。完整进度见[第五步实施与验收](第五步实施与验收_20261108_v1.md)。

## 安装与运行

前端使用 Vue 3 + JavaScript，业务服务使用 FastAPI + MySQL。模型通过外部 HTTP API 调用；SymPy 在 CPU 上进行适用数学检查。

在项目根目录安装后端：

```bash
python -m venv backend-business/.venv
backend-business/.venv/bin/pip install -e backend-business
```

复制 `backend-business/.env.example` 为 `.env`，按第四步说明设置独立 MySQL、原图目录与初始化账号。复制 `backend-business/config/model_pool.example.json` 为同目录的 `model_pool.json`，填写实际供应商服务地址、模型、能力及凭据环境变量名；实际密钥写入环境或本地忽略的 `.env`。两个真实配置文件均不提交。

默认配置文件位置由工程自行定位；需要其他文件时设置 `SCZX_MODEL_CONFIG`。配置文件是 `{"entries": [...]}`，每项包含：

|字段|含义|
|---|---|
|name|运行记录中的可读服务名称|
|base_url|兼容服务的 API 根地址，通常包含版本前缀|
|api_key_env|保存该项凭据的环境变量名|
|model|服务实际支持的模型标识|
|capabilities|`text`、`ocr`、`embedding`、`rerank`、`asr`、`tts` 中该模型明确支持的能力|
|disabled|为 true 时停用该项|
|timeout_seconds|可选；单次 HTTP 请求超时，1至120秒，默认100秒；作业整体上限150秒|
|protocol|重排可用 `standard` 或 `chat_rerank`。后者明确通过文本模型语义排序，模型和相对分值含义保存在结果中|
|json_mode|可选；文本/图文是否先请求 JSON 模式，默认开启；不支持时有协议回退|
|paths|可选；按能力覆盖相对路径，例如 `{"rerank":"/v2/rerank"}`。前缀与 base_url 不应重复|
|voice|可选；TTS 使用的服务音色，默认 alloy，必须由供应商实际支持|

当前适配协议：文本/图文使用兼容 chat/completions 的消息结构；Embedding 使用 embeddings 的有序向量响应；Rerank 使用 query/documents 与带 index 的 results；ASR 使用 audio/transcriptions 的 multipart 文件；TTS 使用 audio/speech 的音频响应。地址、模型和路径须按具体服务文档配置；仅换路径不能代替不同请求结构的专用适配。

若使用 LLM 重排，可在重排配置中明确设置 `protocol: "chat_rerank"` 并指定实际可用的文本模型。结果须包含全部候选的唯一 ID 和降序相关分值，分值只表示同组候选的相对相关程度，不作为正确概率，也不冒充标准重排端点的原生分值。

升级已有运行环境时，先停止业务服务，再迁移并启动，避免迁移期间新旧代码同时写入。在 `backend-business` 目录执行：

```bash
.venv/bin/python -m sczx_business.commands migrate
.venv/bin/python -m sczx_business.commands seed
.venv/bin/python -m uvicorn sczx_business.main:app --host 127.0.0.1 --port 8000
```

当前任务工作循环与 API 位于同一服务进程，按单个 uvicorn worker 启动。`seed` 保留既有内容；模型任务启动前需要完成迁移。运行数据包括 MySQL 和 `SCZX_STORAGE_DIR` 的文件目录，不应只保存网页文件。

另一终端在项目根目录执行：

```bash
npm --prefix frontend ci
npm --prefix frontend run dev
```

打开 Vite 输出地址，默认端口 5177。`/api` 代理指向本机 8000，可通过 `SCZX_API_PROXY` 更改。生产构建：`npm --prefix frontend run build`。

## 学生与教师操作

1. 沿用第四步账号与班级：教师备课发布任务，学生进入“我的学习”。
2. 在学习助手输入问题，或选题图后点击“识别题图”。题图先保存为文件资源。
3. 识别完成后对照原图修订题目，再点击“确认题目并获取提示”。识别原文、修订内容和指导作业分开保存。
4. 指导先显示提示，可展开分步讲解。数学标签只代表列出的表达式等价性核对；“需核对”不等于判错。
5. 独立检查中请求帮助会关联当前题目；换题后重新记录独立性。作答和固定补救练习由后端检查表达式等价性，原作答与解释保留。
6. 教师在学情页打开学生过程，查看原图、学生确认题目、识别/指导结果及作答补救，随后保存教师反馈；模型结果不会覆盖教师反馈。

页面离开后服务端任务继续执行。重新进入页面会读取最近任务；事件连接断开时通过详情读取恢复状态。任务失败保留输入与已有结果，支持手动重试。运行中不能重复手动重试，相同进行中输入有数据库去重约束。

## 管理端能力与运行记录

管理员打开“反馈与运行”中的“模型与任务”，选择六类能力之一。

- 文字指导：输入教学问题，查看结构化提示和分步结果。
- 题图识别：上传图片，查看原文、数学表达和识别疑点。
- 文本向量：每行一段文本，查看数量与维度；完整向量保存在作业详情中。
- 材料重排：输入问题及每行一段候选材料，查看候选编号与相关分值；LLM 协议明确标示分值为同组相对相关程度。
- 语音转写：上传真实音频，查看转写；修改后“保存修订”，保留原转写，并可送到讲解音频入口。
- 讲解音频：输入文字，调用外部 TTS，保存并播放结果文件。

当前上传图片与音频均限制 12 MB。已配置不等于调用成功；页面展示实际最近成功或失败。只有真实服务响应才构成能力验收，临时故障模拟与协议校验单独记录。

服务自动重试只针对可恢复错误，最多两次；限流冷却遵循响应可解析的 Retry-After，上限 60 秒。结构错误重试要求重新组织 JSON。无配置、认证错误等直接失败并提示。服务重启时保留已成功结果，将中断执行记录为失败并允许手动重试；不自动重跑可能已经产生外部请求的中断任务。

## 接口与数据

|接口|用途|
|---|---|
|GET /api/ai/capabilities|管理员查看配置及最近调用状态|
|POST /api/ai/jobs|创建模型作业，携带 requestKey、capability、必要 recordId/fileId 和 data|
|GET /api/ai/jobs|按当前角色读取最近作业，可用 recordId 筛选|
|GET /api/ai/jobs/{id}|读取输入、规范化结果和执行尝试|
|GET /api/ai/jobs/{id}/events|SSE 步骤事件，支持 Last-Event-ID 或 after 游标|
|POST /api/ai/jobs/{id}/retry|创建同一逻辑作业的下一次执行，保留旧记录|
|PUT /api/ai/jobs/{id}/correction|保存本人成功 ASR 作业的修订文字，保留原转写|

MySQL 的 `model_jobs` 保存业务关联和输入/结果，`model_runs` 保存每次执行，`model_events` 保存可恢复步骤。`active_hash` 的唯一约束限制同一账号同输入至多一个进行中任务。新增模型作业时间统一保存 UTC 并显式返回时区；旧教学记录沿用原格式。

当前迁移为 `0005_model_job_deduplication`。任务创建后先持久化再执行外部请求；外部调用期间不保持业务数据库事务。前端自动保存不负责覆盖模型作业结果。

## 当前边界

本步不包含完整 RAG 索引、Agent 教学编排或学生连续语音产品，按后续计划推进。现有课程和固定练习属于明确的首课内容；自然语言解释与数学符号检查分别保存，数学程序不能验证所有题型。

当前环境中 ASR、TTS 尚无成功的真实验收结果。标准专用 Rerank 端点暂不可用，LLM 语义重排已完成真实验证。已经实现适配和页面不能替代实际服务验证；补齐配置后还需完成真实转写、修订、合成与生成音频的浏览器播放检查。
