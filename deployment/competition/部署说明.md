# 错题帮可运行程序包部署说明

## 一、交付内容

本包对应“可运行程序包及部署文档”的交付用途。浏览器打开学生界面，仓颉服务处理账号、错题和学习记录，Python 服务执行算法，MySQL 保存业务数据。Docker 镜像中包含已构建的 H5 页面、仓颉可执行文件、Python 及依赖、MySQL、BGE 检索模型和语音识别模型；另附 Qdrant 镜像。无需现场编译仓颉或下载 Python 依赖。

本包采用便于评审的单机部署：应用容器内部运行独立的业务、算法、检索计算及数据库进程，Qdrant 使用单独容器。进程职责与源码保持一致，Python 算法服务不读写业务数据库。该组织方式用于本地演示，不是面向高并发的生产集群方案。

## 二、环境要求

目标平台为 Linux x86_64，已安装并启动 Docker Engine。建议提供至少 16 GB 内存、4 核 CPU，并为镜像导入及数据预留 40 GB 磁盘空间；BGE 首次加载较慢。最低资源占用未单独测定。无须 GPU。Windows、macOS 和 ARM 设备不作为本包已验证平台。

本包包含本地程序和模型，AI 解题、图片识别等功能仍通过外部 AI 接口运行，需要网络和有效密钥；语音合成也需要访问外部服务。镜像可从包内离线导入，但这不代表全部 AI 能力能够断网使用。

## 三、启动步骤

1. 解压压缩包，进入包含 start.sh 的目录。路径建议使用英文，保留全部文件。
2. 执行 `bash start.sh`。第一次会生成 .env，并提示填写配置。
3. 用文本编辑器打开 .env，在 `XIAOJING_API_KEY=` 后填写评审期间有效的密钥，不加引号。不要把填写后的文件上传到 GitHub。
4. 再执行 `bash start.sh`。脚本会自动导入镜像、建立独立网络与数据卷，然后启动服务。首次导入需要一定时间。
5. 执行 `bash check.sh`，检查业务、算法、检索计算、检索存储和页面是否可访问。
6. 浏览器打开 `http://127.0.0.1:5175`，进入注册页创建自己的学生账号，再开始使用。

默认没有预置学生账户和个人错题。注册采用应用自身注册流程。包内提供 24 道自编方程演示题，以及项目公开知识内容。演示题用于检查练习、考试和保存流程，不代表完整学科题库或真实学生测评数据。

如果 5175 端口已被占用，可执行 `CUOTI_PORT=5176 bash start.sh`，改用 5176 访问。其他端口只在容器内部使用，不占用宿主机 MySQL、业务和算法端口。

需要同一局域网设备访问时，可执行 `CUOTI_BIND=0.0.0.0 bash start.sh`，再在手机浏览器访问电脑的局域网 IP 和端口。该入口仍为 HTTP，手机相机、麦克风等权限是否开放取决于浏览器；正式手机访问应另配 HTTPS。本次交付不包含签名 APK。

## 四、配置与数据保存

密钥通过 .env 注入算法服务。API 配置与当前项目一致，包内仅保留环境变量名，不包含实际密钥。没有密钥时仍可启动基础页面、注册和保存手动错题，但涉及 AI 的请求可能明确报错，不能视为全功能验收通过。

首次启动会创建全新的 MySQL 数据目录、业务数据库以及随机数据库密码、登录签名密钥和内部服务密钥。它们保存在 `cuoti-delivery-data` 数据卷中。学生错题、上传图片和学习记录也保存在该卷；检索索引保存在 `cuoti-delivery-index` 卷。

执行 `bash stop.sh` 只停止本包容器，不删除数据。重新运行启动脚本会读取新的 .env 并复用已有数据。不要执行删除上述数据卷的命令，否则会丢失评审期间录入的内容。切换机器时，应在应用停止后迁移整个数据卷，而不只是复制镜像。

脚本使用专属容器名 `cuoti-delivery-app` 和 `cuoti-delivery-qdrant`，并检查容器标签，避免误操作同名的其他容器。不会重置宿主机数据库，不会读取项目原有学生数据。

## 五、功能验收

按《功能验收说明.md》依次体验注册、手动录题、图片识别、错因分析、订正与独立作答、类似题、题库练习、模拟考试、复习、报告和导出。AI 结果应结合具体题目检查，联网或额度异常时先解决服务配置。

`check.sh` 检查服务能否访问，不消耗 AI 接口额度，也不等同于模型回答正确。实际交付验证情况以包内《验收记录.md》为准，其中区分容器运行、数据保存、AI 调用和界面验证。

## 六、常见问题

**Docker 无法连接：** 启动 Docker 服务，确认当前用户有使用 Docker 的权限。程序启动脚本不会修改系统 Docker 配置。

**页面暂时打不开：** 首次启动需初始化数据库。先执行 check.sh，再查看 `docker logs --tail 100 cuoti-delivery-app`。不要通过删除数据目录解决已有数据库问题。

**端口被占用：** 使用 CUOTI_PORT 改为其他空闲端口，然后按提示访问。

**AI 请求失败：** 检查 .env 中密钥是否正确、接口额度是否有效，以及当前网络能否访问服务。修改 .env 后重新执行 start.sh，使新配置进入容器。对外提供日志时先检查其中是否包含个人题目或服务信息。

**检索第一次很慢：** CPU 需要加载 BGE 模型并处理文本。检查可用内存和容器日志，等待首次模型加载完成。不要把检索计算服务的健康响应误认为模型已经完成加载。

**容器因内存不足退出：** 增加 Docker 可用内存后重启。已有数据卷不需要重新初始化。

**停止或重启：** 使用 stop.sh 和 start.sh。不要停止其他项目容器，不需要清理 Docker 历史镜像。

## 七、Compose 替代入口

附带 compose.yaml，供已经安装 Docker Compose 的环境使用。先执行 `docker load -i images.tar.gz`，复制 configuration.env.example 为 .env 并填写密钥，再执行 `docker compose up -d`。Compose 与 start.sh 使用不同的容器和数据卷；同一台机器只选择一种启动方式，避免占用同一端口或误以为两者共享数据。本次验收以 start.sh 入口为准。
