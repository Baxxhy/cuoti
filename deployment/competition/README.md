# 参赛可运行程序包

运行用户请阅读交付 ZIP 内的《部署说明.docx》或《部署说明.md》。默认使用 Docker Engine 与 start.sh，不依赖 Compose。该包不包含学生数据或 API Key，首次启动创建独立数据库，评委自行注册。

本目录保留启动脚本、部署网关、初始化入口、自编演示题及验收工具。业务代码不在本次打包过程中改写。gateway.py 只转发学生 HTTP 请求和提供构建后的页面，不承担业务数据库操作。

构建过程先从已经运行的 Linux x86_64 环境暂存已编译仓颉程序及 Python 3.13 依赖，补齐动态库，形成运行镜像；再加入经过实际计算检查的 CPU 检索环境、BGE 模型和语音识别模型。运行镜像及 Qdrant 镜像一同导出，交付包包含校验清单。

prepare_payload.py 是当前构建主机的资源收集工具，依赖本仓库的构建产物和 /root/miniconda3；它不是面向评委的安装脚本。Dockerfile.models 使用中间运行镜像作为基础。两套 Python 依赖的锁定清单用于记录算法环境与检索环境的区别。重新构建时还需按模型仓库来源准备缓存，不能只拿 Dockerfile.models 就假定依赖已经齐备。

验收脚本仅应指向本包创建的独立测试环境。smoke_delivery.py 会注册测试用户和写入自编错题，并可用 --ai 发起真实 AI 请求；不要对真实学生数据库运行。正式 ZIP 不包含验收账户密码。

公式导出依赖通过 prepare_exports.py 收集：复用已安装 Node、前端公式渲染源码、pnpm 依赖和 Chromium，再加入中文字体。收集新依赖时保留算法环境已有的同名动态库，避免浏览器系统库覆盖 Python 需要的版本。最终交付以已经构建并验收的镜像为准。
